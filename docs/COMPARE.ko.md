# Sprag와 ccusage, claude-usage, 스테이터스라인 도구 비교

[← README](../README.ko.md) · [English](./COMPARE.md)

ccusage, claude-usage, CCometixLine 같은 스테이터스라인 도구와 Sprag를 비교하고 있다면, 이 도구들은 클로드 코드가 이미 쓴 돈을 보여 주고 Sprag도 그 일을 하지만, 거기서 발견한 패턴을 실제로 처리해서 반복 작업을 싼 모델에 위임까지 한다는 차이가 있습니다. 둘은 서로 배타적이지 않습니다. Sprag의 스테이터스라인은 현재 세션 중심이라 과거 기록을 길게 보여주지 않으므로, 장기 사용량 대시보드를 따로 두고 Sprag 스테이터스라인을 함께 쓰는 사람도 많습니다.

## 나뉘는 지점: 보여주기와 처리하기

**ccusage**, **claude-usage**, **CCometixLine** 모두 클로드 코드가 로컬에 남기는 세션 로그를 읽어서 보고서로 바꿔 줍니다. 토큰 수, 모델별 분류, 비용 추정, 터미널 프롬프트 안의 깃·컨텍스트 정보까지 형태는 다르지만(CLI 리포트, 웹 대시보드, 스테이터스라인) 다들 이 숫자를 눈에 보이게 만듭니다. 보이지 않으면 고칠 수도 없으니 이건 그 자체로 유용한 일입니다.

다만 셋 다 다음 요청에서 벌어질 일을 바꾸지는 않습니다. 어떤 세션이 비쌌다고 알려 줄 뿐, 다음에도 같은 방식으로 비쌀 일을 막아 주지는 않습니다. Sprag의 `route-scan`이 메우는 게 바로 이 빈틈입니다. 같은 종류의 세션 로그를 읽되, 비싼 모델이 반복해서 처리한 요청 패턴을 찾아내서 다음 세션부터 그 패턴을 싼 서브에이전트로 자동 위임하는 룰을 씁니다. 보고 계층과 처리 계층은 서로 부딪히지 않으니 둘 다 같이 써도 됩니다.

## ccusage

[ccusage](https://github.com/ryoppippi/ccusage)는 코딩 에이전트 CLI의 토큰 사용량과 비용을 로컬 데이터로 분석하는 도구입니다. CLI 중심이고 채택 폭이 넓어서(README에 어썸 클로드 코드 배지와 트렌드시프트 배지가 붙어 있습니다) 클로드 코드가 남기는 것과 같은 JSONL 세션 트랜스크립트를 읽습니다. 사후 비용 보고 쪽에서는 사실상 표준에 가깝습니다.

ccusage가 멈추는 지점은 여기까지입니다. 일어난 일을 알려 줄 뿐, 진행 중인 세션의 캐시 적중률이나 사용 한도를 실시간으로 지켜보지도, 미래 모델 선택을 바꾸는 룰을 만들지도 않습니다. "돈이 어디로 샜는지 주간 리포트로 확인한다"가 워크플로라면 ccusage만으로 충분합니다. 지금 세션의 캐시 상태와 한도 여유까지 프롬프트에서 바로 보고, 반복되는 비싼 패턴을 싼 서브에이전트로 자동 넘기고 싶다면 그 부분이 Sprag가 더하는 몫입니다.

## claude-usage

[claude-usage](https://github.com/phuryn/claude-usage)(Claude Code Usage Dashboard)는 자기 위치를 스스로 명확히 밝힙니다. "Pro와 Max 구독자는 진행 막대를 받지만, 이 도구는 전체 그림을 보여 준다"고 적혀 있습니다. 같은 로컬 로그를 읽어서 웹 대시보드나 VS Code 확장으로 차트와 비용 추정치를 보여 주고, API·Pro·Max 플랜 전반에서 CLI, VS Code 확장, 디스패치된 Code 세션의 사용량까지 추적합니다(서버에서 돌아 로컬 트랜스크립트가 없는 Cowork 세션은 못 봅니다).

이 도구는 터미널 스테이터스라인으로는 보여 줄 수 없는 대시보드와 차트, 즉 깊이 있는 가시성에 강점이 있습니다. 모델 라우팅에는 관여하지 않고 위임 룰도 쓰지 않는, ccusage와 마찬가지로 읽기 전용 경로입니다. Sprag의 실시간 스테이터스라인과 route-scan 위임 위에 이런 장기 대시보드를 얹고 싶다면 함께 쓰는 게 자연스럽습니다.

## 스테이터스라인 도구(CCometixLine)

[CCometixLine](https://github.com/Haleclipse/CCometixLine)은 러스트로 짠 클로드 코드용 스테이터스라인으로, 깃 연동, 트랜스크립트 분석 기반 사용량 추적, 대화형 TUI 설정, 클로드 코드 보강 유틸리티(컨텍스트 경고 비활성화, 상세 모드 활성화 등)를 담고 있습니다. 모델, 디렉터리, 깃 상태, 컨텍스트 윈도우 정보를 보여 주는 빠르고 커스터마이징 가능한 프롬프트 세그먼트가 초점이고, 테마 시스템과 세그먼트 단위 설정을 갖추고 있습니다.

Sprag의 스테이터스라인은 같은 위치에서 다른 걸 보여 줍니다. 프롬프트 캐시 적중률, 캐시 TTL 카운트다운, 5시간·주간 두 사용 한도의 리셋 시각, 그리고 위임 기록이 쌓이면 무엇을 얼마나 절감했는지 보여 주는 라우팅 절감 줄까지입니다. 세션이 스스로 정한 운영 원칙을 지키고 있는지 보여 주는 하네스 점수(`🅷 5/5`)도 함께 띄웁니다. CCometixLine의 TUI 커스터마이징이나 클로드 코드 패치 유틸리티는 Sprag가 다루는 영역이 아니라서, 그 수준의 테마 커스터마이징이 필요하다면 그쪽이 강점입니다. 둘을 같은 스테이터스라인 슬롯에 동시에 띄우도록 만들어지진 않았지만, 캐시·한도 칩은 Sprag로 보면서 CCometixLine의 테마 아이디어를 참고하는 식으로 쓰는 건 얼마든지 가능합니다.

## Sprag가 구체적으로 다른 부분

- **route-scan**은 패턴을 보여 주기만 하지 않고 승인한 범위 안에서 위임 룰을 직접 써서, 다음 세션부터 그 요청 유형이 하이쿠나 소네트 서브에이전트에서 돌게 만들고, 위임된 실행마다 절감액을 원장에 기록해 `sprag route-scan savings`로 검증할 수 있게 합니다. 자세히: [route-scan](./ROUTE_SCAN.ko.md)
- **하네스**는 반복된 실수를 매 세션 로드되는 룰로 바꿉니다(클로드 코드는 `CLAUDE.md`, 코덱스는 `AGENTS.md`). 같은 교정 비용을 한 번만 치르면 됩니다. 자세히: [harness](./HARNESS.ko.md)
- **doc2md**는 pptx, xlsx, pdf, docx, 피그마 파일을 컨텍스트에 들어가기 전에 마크다운으로 바꾸는데, 이건 위 보고 도구들이 하지 않는 토큰 회피 단계입니다. 자세히: [doc2md](./DOC2MD.ko.md)
- **메인 세션의 모델은 건드리지 않습니다.** 프롬프트 캐시가 모델별로 따로 유지되기 때문에, Sprag는 세션 중간에 모델을 바꾸는 대신 서브에이전트로 위임합니다. 자세히: [실시간 라우팅이 더 비싼 이유](./NOT-A-ROUTER.ko.md)

```bash
npm i -g sprag-cli
```
