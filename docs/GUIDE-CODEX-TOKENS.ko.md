# 코덱스 CLI 토큰 사용량 줄이는 법

[← README](../README.ko.md) · [English](./GUIDE-CODEX-TOKENS.md)

클로드 코드 토큰을 줄일 때 쓰는 습관은 코덱스 CLI에도 그대로 통합니다. 세션 범위를 좁혀서 오래된 맥락이 계속 남지 않게 하고, 읽을 게 많은 탐색 작업은 메인 스레드 대신 서브에이전트로 넘기고, 큰 문서는 붙여넣거나 첨부하기 전에 마크다운으로 바꾸는 것입니다. 코덱스 자체 사용량 집계는 클로드 코드와 완전히 분리돼 있어서 세션도, 캐시도, 지출 합계도 서로 섞이지 않지만, 비용을 좌우하는 근본 요인은 같습니다. 컨텍스트에 쌓인 토큰이 이후 매 턴 다시 청구된다는 점입니다.

## 세션을 계속 키우지 말고 범위를 나누세요

관련 없는 작업을 계속 이어 붙인 코덱스 세션은 이전 작업의 맥락을 전부 다음 턴까지 끌고 갑니다. 작업이 실제로 바뀌는 시점에 새 세션을 시작하거나 맥락을 초기화하면, 각 세션의 누적 맥락이 그날 터미널에서 일어난 모든 일이 아니라 그 작업에 실제로 필요한 만큼으로 유지됩니다.

## 반복되는 정형 작업은 싼 모델에 위임하세요

코덱스는 네이티브 서브에이전트 스폰(`spawn_agent`)을 지원하고, 호출마다 모델과 추론 강도를 따로 지정할 수 있습니다. 비용을 줄이는 지렛대가 바로 이 지점입니다. 읽을 게 많고 결과는 짧고 검증하기 쉬운 작업은 이를 지시하는 메인 세션과 같은 모델·같은 강도가 필요하지 않습니다. 조회, 번역, 붙여넣은 내용 설명 같은 유형을 호출 단위로 싼 모델에 보내면, 메인 세션의 모델과 강도는 실제 판단이 필요한 작업을 위해 그대로 남겨 둘 수 있습니다.

클로드 코드에서 세션 중간에 모델을 바꾸지 말라는 원칙은 여기서도 비슷하게 적용됩니다. 메인 세션 자체의 모델을 비용 때문에 바꾸면 런타임이 모델별로 캐시나 상태를 유지하는 경우 숨은 손해가 생깁니다. 그래서 싼 모델을 들여오는 지점은 메인 세션이 아니라 범위가 정해진 서브에이전트 호출 쪽이 안전합니다.

## 큰 문서는 컨텍스트에 들어가기 전에 변환하세요

PDF, 스프레드시트, 슬라이드 덱을 그대로 첨부하면 실제 내용이 아니라 파일이 포장된 방식에 비례한 토큰이 듭니다. 슬라이드 덱 하나의 내부 XML은 태그와 스타일 속성까지 합치면 수십만 토큰까지 늘어날 수 있습니다. 먼저 마크다운으로 변환하면 내용은 남기고 포장만 걷어낼 수 있습니다. 이 원칙은 형식을 가리지 않고, 변환을 손으로 하든 도구로 하든 마찬가지며, 코덱스로 들어가기 전에도 클로드 코드로 들어가기 전과 똑같이 적용됩니다. 실측 수치는 [doc2md](./DOC2MD.ko.md) 문서에 있습니다. 클로드 코드 첨부 기준으로 잰 값이지만, 포장과 내용 사이의 격차 자체는 특정 클라이언트에 국한된 얘기가 아닙니다.

## Sprag가 코덱스에 더하는 것

Sprag는 코덱스의 네이티브 `AGENTS.md`와 `hooks.json` 인터페이스로 코덱스를 지원하며, 클로드 코드 통합과 나란히 설치할 수 있습니다. 하나를 설치했다고 다른 하나가 필요해지거나 꺼지지 않습니다. `--agent codex`를 붙이면 코덱스를 명시적으로 지정합니다.

```bash
npm i -g sprag-cli
sprag install --agent codex
```

이 설치로 켜지는 것들입니다.

- **`AGENTS.md`에 심어지는 하네스 룰.** 클로드 코드와 같은 래칫 메커니즘입니다. 반복된 실수가 매 세션 로드되는 한 줄 룰이 되는데, 대상 파일만 `CLAUDE.md`가 아니라 코덱스의 자체 지침 파일입니다.
- **세션에 붙는 컴패니언 패널.** macOS zsh 환경에서는 설치 과정이 tmux를 준비해서 `codex`를 입력할 때 같은 터미널 안에 패널이 인라인으로 뜨게 합니다. tmux가 없거나 로그인 셸이 zsh가 아니거나 기존 `codex` 별칭이 있으면 별도 창으로 대체됩니다.
- **선택적으로 켜는 위임 기능.** `sprag delegate on --agent codex`로 따로 켭니다. 켜고 나면 `sprag delegate model <모델ID> --effort <강도> --agent codex`로 모델 지정 없는 기본 스폰의 대상을 정할 수 있고, `sprag delegate rules add explore --from <모델> --model <싼 모델> --project --agent codex` 같은 카테고리 룰로 특정 요청 유형만 싼 모델로 보내고 나머지는 부모 모델에 그대로 둘 수 있습니다. 매칭은 카테고리·프로바이더·정확한 부모 모델 기준으로 좁혀지고, 프로젝트 룰이 글로벌 룰보다 우선합니다.
- **문서 변환과 진단.** 클로드 코드와 같은 doc2md 파이프라인을 쓰고, 설치 후에는 `sprag panel doctor --agent codex`로 훅 실행 여부, 실행 실패, 최근 렌더된 프레임을 확인할 수 있습니다.

코덱스 사용량 집계는 두 통합 사이에 공유되는 지출 합계나 캐시 타이머 없이 끝까지 클로드 코드와 분리됩니다. 전체 레퍼런스는 [코덱스 통합](./CODEX.ko.md) 문서에 있습니다.

```bash
npm i -g sprag-cli
sprag delegate on --agent codex
```
