# 팀 기능

[← README](../README.ko.md) · [English](./TEAM.md)

Sprag 은 기본적으로 로컬에서만 동작합니다. 팀 기능은 켜야만 쓰이는 선택 기능입니다. 팀원마다 하루 지출과 절감액을 한 대시보드에서 보고, 오너나 어드민이 승인한 래칫 룰을 함께 쓸 수 있습니다. `sprag team join <토큰>` 을 실행하거나 환경에 `SPRAG_TEAM_TOKEN` 을 지정하기 전에는 아무것도 전송하지 않습니다. `SPRAG_NO_TEAM_SYNC=1` 을 지정하면 다른 설정과 상관없이 사용량 업로드가 모두 멈춥니다.

## 보내는 것과 보내지 않는 것

참여하면 Sprag 은 로컬 날짜 기준으로 하루에 한 행씩 올립니다.

| 항목 | 내용 |
|---|---|
| 지출(USD) | 로컬 세션 로그로 계산한 금액 |
| 절감(USD) | 라우팅 원장과 doc2md 원장에서 가져온 금액 |
| 위임 실행 횟수 | 그날 위임한 실행의 수 |
| 모델 계열 비중 | 위임 실행 중 모델 계열별 비율 |
| Sprag 버전 | 설치된 버전 |
| 에이전트 | `claude` 또는 `codex` |
| 표시 이름 | 참여할 때 정한 이름이며, 기본값은 OS 사용자 이름 |

보내지 않는 것은 프롬프트, 대화 기록, 파일 경로, 프로젝트 이름, 룰 내용, API 키입니다. 룰은 직접 `sprag team propose` 를 실행할 때만 밖으로 나갑니다.

업로드는 6시간에 한 번 이하로 실행됩니다. SessionStart 훅이 띄운 분리된 자식 프로세스가 보내며, statusline 을 그리는 경로에서는 절대 실행되지 않습니다.

목적지는 `https://hiycfjwswtkixyoqkznm.supabase.co/rest/v1/rpc/*` 입니다(Supabase, ap-northeast-2 리전). 호출하는 RPC 는 `team_join`, `ledger_upsert`, `team_rules_get`, `team_rule_propose`, `team_leave`, `member_set_sync`(업로드 스위치 상태 호출, "업로드 스위치" 참고) 입니다.

## CLI에서 팀 만들기

웹 대시보드 없이 팀을 만들 수 있습니다. 로그인은 메일로 받는 6자리 코드(15분간 유효)로 하며, Sprag 은 로그인 세션을 저장하지 않습니다.

터미널에서는 명령 하나를 실행하고 묻는 대로 답하면 됩니다 (이메일, 코드, 팀 이름).

```bash
sprag team create
```

에이전트나 터미널이 없는 셸에서는 두 단계로 나눕니다.

```bash
sprag team create --email you@example.com --name "Acme"
# 메일로 코드가 오면 이어서 실행합니다
sprag team create --email you@example.com --name "Acme" --code 123456
```

첫 단계는 코드만 보냅니다. 두 번째 단계에서 코드를 확인하고 팀을 만든 뒤 초대 토큰, 멤버용 명령(`npm i -g sprag-cli@latest && sprag team join <토큰>`), 조직용 환경 변수(`export SPRAG_TEAM_TOKEN=<토큰>`), 대시보드 주소를 출력합니다. 같은 이메일로 https://sprag.io/team/ 에 로그인하면 팀을 관리할 수 있습니다.

기본적으로 이 PC가 첫 멤버로 참여하고 동기화를 한 번 실행합니다. 참여하지 않으려면 `--no-join` 을 붙입니다. 이미 팀에 참여한 PC에서는 먼저 `sprag team leave` 를 실행하거나 `--no-join` 을 붙여야 합니다.

## 개인으로 참여하기

오너나 어드민에게 초대 토큰을 받은 뒤 실행합니다.

```bash
sprag team join <토큰> --name "미나"
```

Sprag 이 올라갈 항목 목록을 보여 주고 확인을 묻습니다. `--name` 은 표시 이름이며 기본값은 OS 사용자 이름입니다. 터미널이 없는 셸에서는 `--yes` 를 붙여 확인을 대신합니다. 토큰을 생략하면 `SPRAG_TEAM_TOKEN` 을 읽습니다.

결과는 `sprag team status` 로 확인합니다.

## 조직 단위로 등록하기

구성원이 각자 명령을 실행하지 않아도 모든 컴퓨터를 등록하려면 환경에 `SPRAG_TEAM_TOKEN=<토큰>` 을 지정합니다. 흔한 위치는 두 곳입니다.

- 셸 프로필: `export SPRAG_TEAM_TOKEN=<토큰>`
- Claude Code 관리 설정: `{"env":{"SPRAG_TEAM_TOKEN":"…"}}`

컴퓨터는 다음 세션이 시작될 때 참여합니다. 그다음 첫 세션에는 팀 이름과 두 명령을 알리는 한 줄 안내가 나옵니다. `sprag team status --show-payload` 는 보내는 내용을 보여 주고, `sprag team leave` 는 전송을 멈춥니다.

`leave` 는 환경 변수보다 우선합니다. 팀에서 나온 컴퓨터는 변수가 남아 있어도 저절로 다시 참여하지 않습니다. 오너나 어드민이 새 토큰을 발급하고 구성원이 `sprag team join` 을 다시 실행해야 다시 참여합니다.

## 팀 룰

오너와 어드민은 대시보드에서 룰을 승인합니다. 구성원도 룰을 제안할 수 있습니다.

```bash
sprag team propose "커밋 전에 lint 실행" --scope ratchet
```

`--scope` 는 `ratchet`(기본값) 또는 `model` 입니다. 제안은 오너나 어드민이 승인할 때까지 대기 상태로 남습니다.

승인된 룰은 다음 동기화 때 내려옵니다. Sprag 은 이를 `~/.claude/ratchet-team.md`(Codex 는 `<CODEX_HOME>/ratchet-team.md`)에 쓰고, 그 파일이 있는 동안 `~/.claude/CLAUDE.md` 의 전역 harness 블록에서 import 합니다. Sprag 이 세션을 시작할 때 파일을 통째로 다시 쓰므로 직접 고치지 마십시오. `sprag team rules` 는 받아 둔 룰을 보여 줍니다. `sprag team leave` 는 멤버 키, 캐시, import 를 지웁니다.

## 상태 확인, 전송 내용 확인, 나가기

| 명령 | 설명 |
|---|---|
| `sprag team join [토큰] [--name <이름>] [--yes]` | 팀에 참여 |
| `sprag team status [--show-payload]` | 팀, 플랜, 프롬프트 수집 설정, 표시 이름, 마지막 동기화를 보여 줍니다. `--show-payload` 를 붙이면 올라갈 하루 단위 행도 그대로 출력합니다 |
| `sprag team sync [--force]` | 지금 업로드하고 룰을 받습니다. `--force` 는 6시간 간격을 무시합니다 |
| `sprag team rules` | 받아 둔 팀 룰 보기 |
| `sprag team propose "<내용>" [--scope ratchet\|model]` | 팀에 룰 제안 |
| `sprag team leave` | 팀에서 나가고 업로드 중단 |

## 조직과 좌석

모든 팀은 조직에 속하고, 좌석은 팀이 아니라 조직 단위로 구매합니다. 조직을 지정하지 않고 만든 팀에는 조직이 자동으로 새로 생기므로 기존 설정은 그대로 동작합니다.

- **좌석이란.** 팀을 떠나지 않았고, 최근 30일 안에 무엇이든 보냈거나 업로드를 멈춘 상태인 컴퓨터 한 대(멤버 키 하나)입니다. 멈추지 않았는데 30일 넘게 연락이 없는 컴퓨터는 좌석을 차지하지 않습니다. 떠난 멤버도 세지 않습니다.
- **두 번째 컴퓨터.** 같은 사람이 컴퓨터 두 대를 쓰면 오너나 어드민이 두 번째 컴퓨터를 첫 번째에 합쳐 좌석 하나를 같이 쓰게 할 수 있습니다. 대시보드의 멤버 행에서 "자리 합치기"를 누르고, "합치기 해제"를 누르면 다시 따로 셉니다. 합쳐진 행에는 "OO님과 자리를 같이 씁니다"가 보입니다.
- **한도.** 조직마다 좌석 한도가 있고, 한도를 넘는 참여는 거절됩니다. `sprag team join` 은 "이 조직에 남은 자리가 없습니다. Sprag 관리자에게 자리 한도를 늘려 달라고 요청한 뒤 다시 참여하세요"를 출력하고 종료 코드 1로 끝납니다. 환경 변수로 하는 자동 참여는 조용히 넘어갔다가 다음 세션 시작 때 다시 시도합니다. 한도를 현재 사용량보다 낮춰도 기존 멤버는 그대로 쓰고, Sprag가 다시 올릴 때까지 새 참여만 거절됩니다.
- **역할.** 권한 단계는 세 가지입니다. 슈퍼유저는 Sprag 직원이며 요금제와 좌석 한도를 정하고, 조직을 정지하고, 오너를 추가하고, sprag.io/ops/ 에서 모든 조직을 봅니다. 오너는 회사의 최상위 단계로, 어드민을 지정하거나 해제하고 어드민이 하는 일을 모두 합니다. 어드민은 회사의 관리 단계로, 팀을 만들고 구성원과 룰과 좌석을 관리합니다. 팀을 만든 사람에게도 특별한 권한이 없으며, 팀은 조직의 오너와 어드민, 그리고 슈퍼유저만 관리합니다. 오너와 어드민은 대시보드에서 좌석 한도를 볼 수 있습니다. 좌석을 늘리려면 sales@sprag.io 로 문의합니다.

기존 조직 안에 팀을 만들려면 `sprag team create --org <조직 ID>` 를 씁니다. 명령은 조직 이름과 사용 중인 좌석 수를 함께 출력하고, `sprag team status` 는 조직 이름을 보여 줍니다.

## 업로드 스위치

`SPRAG_NO_TEAM_SYNC=1`(옛 이름 `CTS_NO_TEAM_SYNC` 도 계속 읽습니다)을 지정하면 모든 사용량 업로드가 멈춥니다. 참여한 컴퓨터는 스위치가 켜진 것을 처음 봤을 때와 다시 꺼졌을 때, 상태만 담은 호출 `member_set_sync` 를 한 번씩 보냅니다. 사용량 데이터는 들어 있지 않습니다. 다시 꺼진 뒤에는 바로 업로드합니다. 이 호출 덕분에 대시보드가 멈춘 컴퓨터와 연락이 끊긴 컴퓨터를 구분합니다. 멈춘 컴퓨터는 오너나 어드민이 내보내기 전까지 좌석을 유지합니다.

## 대시보드

https://sprag.io/team/ 에서 오너나 어드민이 이메일 코드로 로그인하고, 팀을 만들고, 초대 토큰을 받습니다. 여기서 최근 30일 동안의 구성원별 지출과 절감액을 보고, 룰을 승인하거나 삭제하고, 구성원을 내보낼 수 있습니다. 조직 패널에는 요금제, 한도 대비 사용 좌석, 어드민, 전체 팀이 보입니다. 슈퍼유저는 sprag.io/ops/ 에서 모든 조직을 봅니다.

### 좌석 현황

오너와 어드민에게는 /team 에 좌석 현황이 보입니다. 행 하나가 컴퓨터 한 대이고, 다음을 보여 줍니다.

- **업로드 스위치.** 켜짐(On) 또는 꺼짐(Off)
- **신호.** `ok` 는 48시간 안에 업로드한 상태입니다. `late` 는 스위치는 켜져 있는데 48시간 넘게 업로드가 없는 상태입니다. `paused` 는 스위치가 꺼진 상태입니다. `silent` 는 30일 넘게 연락이 없는 상태이며 좌석을 차지하지 않습니다. `left` 는 구성원이 `sprag team leave` 를 실행한 상태, `removed` 는 오너나 어드민이 내보낸 상태입니다.
- **날짜와 버전.** 마지막 업로드, 마지막 연락, 멈춘 시점, Sprag 버전

행에서 할 수 있는 작업은 다음과 같습니다.

- **제거**는 좌석을 비우고, 그 컴퓨터의 키는 더 이상 동작하지 않습니다.
- **복구**는 오너나 어드민이 내보낸 컴퓨터에만 쓸 수 있고, 좌석 한도 안에서만 됩니다.
- **좌석 합치기**와 합치기 해제는 위에서 설명한 대로입니다.

현황 아래의 활동 기록에는 참여, 멈춤, 재개, 탈퇴, 제거, 복구가 누가 했는지(구성원, 오너, 어드민, 슈퍼유저)와 함께 남습니다.

## 플랜

Free, Team(좌석당 월 $5), 비즈니스(좌석당 월 $10, 프롬프트 수집 포함)가 있습니다. 자세한 내용은 https://sprag.io/pricing/ 에 있습니다.

## 개인정보 관련 참고

- 오너와 어드민은 구성원별 하루 합계를 봅니다. 세션이나 프롬프트는 보지 못합니다.
- 구성원은 `sprag team status --show-payload` 로 같은 내용을 직접 볼 수 있습니다.
- 프롬프트 수집은 비즈니스 정책이며, 오너나 어드민이 대시보드에서 켤 수 있습니다. 구성원은 `sprag team status` 에서 설정 상태를 확인합니다. 현재 CLI 는 프롬프트를 아직 올리지 않습니다. 업로드는 이후 별도 릴리스에서 다룹니다.
- 룰 내용은 `sprag team propose` 를 통해서만 밖으로 나갑니다.
