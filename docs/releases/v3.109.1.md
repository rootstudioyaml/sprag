- **Machines on a LiteLLM gateway that never got its price table now price their Claude spend.** The table was fetched only after the statusline's budget check succeeded, so on a gateway where both `/key/info` and `/user/info` fail it never came and every Claude call stayed unpriced. It is now fetched even when the budget check fails, and the team sync fetches it itself once a day; 3.109.0 diagnostics showed claude-opus-5-5 and claude-sonnet-5-5 unpriced for exactly this reason.
- **The first sync that gets the price table re-sends the last 30 days.** Days that went up as unpriced get their spend.
- **Diagnostics keep API paths such as `/key/info` whole.** Only filesystem paths are cut to their last segment, so the failing call can be told apart again.

## 한국어

- **게이트웨이 가격표를 한 번도 받지 못해 Claude 지출이 전부 미산정으로 잡히던 문제를 고쳤습니다.** 가격표는 상태줄의 예산 확인이 성공한 뒤에만 받아 왔습니다. 그래서 `/key/info`와 `/user/info`가 둘 다 실패하는 게이트웨이에서는 가격표 요청까지 가지 못했습니다. 이제 예산 확인이 실패해도 가격표를 받고, 팀 동기화도 하루에 한 번 직접 받습니다. 3.109.0이 보낸 진단에서 claude-opus-5-5와 claude-sonnet-5-5가 이 이유로 미산정이었습니다.
- **가격표를 처음 받은 동기화는 최근 30일을 다시 올립니다.** 그동안 미산정으로 올라간 날도 지출이 채워집니다.
- **진단 메시지에서 `/key/info` 같은 API 경로를 줄이지 않습니다.** 경로를 마지막 조각만 남기는 처리는 파일 시스템 경로에만 적용합니다. 이전에는 어느 호출이 실패했는지 구분할 수 없었습니다.
