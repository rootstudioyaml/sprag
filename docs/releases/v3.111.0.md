- **The reminder to delegate multi-file implementation now actually reaches the model.** The implementation-split clause lived only in text read at session start, so the model often missed it; issue #17 was a session that edited 8 files itself. A prompt that reads as an implementation request or a written spec now gets a one-line reminder, and the main model gets one more notice after editing two code files without delegating. Neither repeats until the next delegation, neither speaks on a Sonnet-or-lower session, and `sprag routing impl off` turns both off.
- **The timing comes from session records.** In turns the main model implemented itself, the share of edit text still to come was 85% after the first code file, 52% after the second and 18% after the third, so the prompt-time reminder is the main device and the edit count moved from three files to two. Documents, memory and scratch paths are not counted, and lookup agents such as Explore or t2 do not count as a delegation. `evals/impl-delegation-rate.mjs` reports the weekly implementation delegation rate and these shares from your own records.
- **The "design judgement stays on main" clause now names the implementation split as its exception.** It read as if it also blocked handing over the code once the main model had settled the design, so the two clauses pulled in opposite directions.

## 한국어

- **여러 파일 구현을 위임하라는 안내가 실제로 나갑니다.** 구현 분업 조항은 세션 시작 때 읽는 문서에만 있어서 모델이 자주 놓쳤고 8개 파일을 메인이 직접 고친 사례가 이슈 #17로 들어왔습니다. 이제 구현 요청이나 긴 지시서로 보이는 프롬프트에 구현 분업 상기가 한 번 붙고, 메인이 위임 없이 코드 파일 두 개를 고치면 한 번 더 알립니다. 두 안내는 다음 위임 전까지 다시 나가지 않고 Sonnet 이하 세션에서는 나가지 않습니다. `sprag routing impl off`로 끌 수 있습니다.
- **알리는 시점은 기록을 재서 정했습니다.** 메인이 직접 구현한 턴에서 아직 쓰지 않은 분량은 첫 코드 파일 뒤 85%, 둘째 뒤 52%, 셋째 뒤 18%였습니다. 그래서 프롬프트 시점을 주 장치로 두고 편집 기준은 두 번째 파일로 당겼습니다. 문서 파일과 메모리, 임시 경로는 세지 않고 Explore나 t2 같은 조회용 에이전트 호출은 위임으로 보지 않습니다. `evals/impl-delegation-rate.mjs`가 세션 기록에서 주별 구현 위임률과 이 분량을 셉니다.
- **"설계 판단이 섞이면 위임하지 않음" 조항에 구현 분업 예외를 붙였습니다.** 메인이 설계를 확정한 뒤 구현만 넘기는 경우까지 이 조항이 막는 것처럼 읽혀 두 조항이 서로 반대로 당겼습니다.
