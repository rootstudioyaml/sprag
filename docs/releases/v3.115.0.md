
- **The statusline no longer re-reads large transcripts on every refresh.** Transcripts of 4MB or more keep their per-request records and read position in a sidecar file, so each refresh reads only the bytes appended since; from a cold cache a render took 0.16s by the third run, where it used to take 4s every time.
- **A statusline render cut off by the 4-second budget keeps what it parsed.** The parse saves its progress every second, so a machine with an empty cache no longer burns 4s of CPU on every refresh without ever catching up, and a render that hits the budget records its parse stats in the diagnostics log.
- **An organisation minimum-version upgrade now starts from sessions that are already open.** The statusline starts it as well as SessionStart, so once an admin raises the minimum, open sessions run the new version from the next refresh.

## 한국어

- **상태줄이 큰 세션 기록을 매번 처음부터 읽지 않습니다.** 4MB 이상 트랜스크립트는 요청 기록과 읽은 위치를 따로 저장해 두고 다음 갱신 때 새로 붙은 부분만 읽습니다. 하루 넘게 열어 둔 세션과 응답 중인 현재 세션이 갱신마다 수백 MB씩 다시 읽히던 문제가 사라졌습니다. 빈 캐시에서 측정하니 3회차부터 한 번 그리는 데 0.16초가 걸렸습니다(이전에는 매번 4초).
- **상태줄이 4초 상한에 걸려도 파싱한 만큼은 남깁니다.** 이전에는 상한에 걸리면 진행분을 버려서 캐시가 비어 있는 기기는 갱신마다 4초씩 CPU를 쓰고 화면은 그대로였습니다. 이제 1초마다 진행분을 저장하고 상한에 걸리면 파싱 통계를 진단 로그에 남깁니다.
- **조직 최소 버전 업그레이드가 열려 있는 세션에서도 시작됩니다.** 지금까지는 새 세션을 열 때만 업그레이드를 시작했습니다. 이제 상태줄 갱신에서도 시작하므로 관리자가 최소 버전을 올리면 세션을 새로 열지 않아도 다음 갱신부터 새 버전으로 돕니다.
