- **Enterprise prompt capture masks network addresses, URLs and file paths and sends the project as an alias.** IP addresses and internal host names in prompt text become `<host>`, URLs outside sprag and Anthropic become `<url>` and absolute paths become `<path>` before upload, and `project` is a `p-` plus 10 hex alias computed with a secret key kept on this machine, the same value `sprag team status --show-payload` shows.
- **The team sync no longer sends sprag's own error messages to the server.** Error text can carry a customer's internal network details, so the upload is gone; the diagnostics log stays on the machine, and the join notice now lists error messages among what is not sent.
- **`sprag team join` shows the cause when it fails at the network level.** Instead of a bare `fetch failed` it names the host it could not reach and the cause code, such as a DNS, proxy, firewall or TLS failure, and network addresses in locally kept error messages are masked.

## 한국어

- **Enterprise 프롬프트 업로드가 네트워크 주소, URL, 파일 경로를 가리고 프로젝트 이름을 별칭으로 바꿉니다.** 프롬프트 본문의 IP 주소와 내부 호스트 이름은 `<host>`, sprag와 Anthropic 등 공개 주소가 아닌 URL은 `<url>`, 홈 디렉터리를 포함한 절대 경로는 `<path>`로 바뀐 뒤에 올라갑니다. 업로드되는 `project`는 폴더 이름이 아니라 이 컴퓨터의 비밀 키로 계산한 `p-` 뒤 16진수 10자 별칭이고, `sprag team status --show-payload`의 예시에도 같은 별칭이 나옵니다. 협력사나 고객사 프로젝트 이름이 서버에 남지 않습니다.
- **팀 동기화가 sprag 자체의 오류 메시지를 더는 서버로 보내지 않습니다.** 오류 문장에는 고객사 내부 망의 주소가 실릴 수 있어서 전송 자체를 없앴습니다. 기기에 쌓는 진단 로그는 그대로 로컬에만 남고 밖으로 나가지 않습니다. `sprag team status`에서 업로드 대기 건수와 진단 기록 출력이 빠졌고 참여 안내 문구는 오류 메시지를 보내지 않는다고 밝힙니다.
- **오류 메시지에 든 네트워크 주소를 가립니다.** 연결 실패 문장에 실리는 IPv4, IPv6, 내부 호스트 이름이 진단 로그에 `<host>`로 바뀌어 저장됩니다.
- **`sprag team join`이 네트워크 단계에서 실패하면 화면에 원인이 나옵니다.** 이전에는 `fetch failed`만 보였습니다. 이제 접속하지 못한 호스트와 DNS, 프록시, 방화벽, TLS 같은 원인 코드가 함께 나옵니다.
