- **The statusline now shows the delegation level being applied.** Above 70% of a usage window a `🔀L1 delegate if unsure` chip appears, and above 90% `🔀L2 delegate multi-step too`. The chip reads the same usage check as the prompt hook, so when it shows, the hook is adding that level's line to delegation hints. `sprag routing status` also prints the current level and what it adds.
- **In auto mode a delegation prompt is no longer sent twice.** When the hook appended guidance to an Agent call's input, auto mode refused the call and the model had to send the same prompt again. In auto mode the input is now left alone and a SubagentStart hook gives the subagent the same guidance as it starts. Upgrading registers that hook during install.
- **English delegation prompts no longer get the Korean style guidance.** A single Hangul character used to attach about 7,000 tokens of guidance. Of 212 real delegations measured, 49 were English prompts that quoted a few Korean strings. The guidance now rides along only when Hangul makes up at least 10% of the letters or the prompt asks for Korean output.
- `npm run presets:pull` keeps the key order of the committed files, so unchanged content leaves them unchanged.
- The team console no longer requests `prompt_days`, which the server never had, so the 404 on page load is gone.

## 한국어

- **상태줄에 지금 적용 중인 위임 레벨이 보입니다.** 사용량 창이 70%를 넘으면 `🔀L1 delegate if unsure`, 90%를 넘으면 `🔀L2 delegate multi-step too` 칩이 뜹니다. 칩은 프롬프트 훅과 같은 사용률 판정을 읽으므로 칩이 보이면 훅도 그 레벨로 위임 안내를 덧붙이고 있습니다. `sprag routing status` 도 현재 레벨과 그 레벨에서 붙는 문구를 알려 줍니다.
- **자동 모드에서 위임 지시문이 두 번 나가지 않습니다.** 훅이 Agent 입력에 지침을 덧붙이면 자동 모드가 그 호출을 거부해서 모델이 같은 지시문을 다시 보내야 했습니다. 이제 자동 모드에서는 입력을 그대로 두고 SubagentStart 훅이 서브에이전트가 시작할 때 같은 지침을 넣습니다. 업그레이드하면 설치 과정이 이 훅을 등록합니다.
- **영어 위임 지시문에는 한국어 문체 지침을 붙이지 않습니다.** 지금까지는 한글이 한 글자만 있어도 약 7천 토큰짜리 지침이 붙었습니다. 실제 위임 212건을 재 보니 49건이 한국어 문자열 몇 개를 인용한 영어 지시문이었습니다. 이제 글자 가운데 한글이 10% 이상이거나 한국어 결과물을 요청할 때만 붙입니다.
- `npm run presets:pull` 이 저장소 파일의 키 순서를 지킵니다. 내용이 같으면 파일도 바뀌지 않습니다.
- 팀 콘솔이 서버에 없는 `prompt_days` 를 더 이상 요청하지 않아 페이지를 열 때 나던 404가 사라졌습니다.
