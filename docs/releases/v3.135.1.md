- **Sprag Bar no longer fails to compile when the same version is reinstalled mid-build.** When `npm install -g` ran alongside session start, npm rewrote `SpragBar.swift` with the same bytes and swiftc failed with "was modified during the build"; the source is now copied before it is compiled. ([#21](https://github.com/rootstudioyaml/sprag/issues/21))
- **A compile failure that a second try fixes is retried at the next session.** Until now any failure held the build back for 24 hours and left the menu bar empty all day; failures caused by the source changing or briefly vanishing are no longer held back.
- **Session start says when the Sprag Bar compile is held back.** One line gives the hours left and the command that fixes it now, `sprag bar build --then-launch`; before, only `sprag bar status` showed it.

## 한국어

- **같은 버전을 다시 설치하는 도중에도 Sprag Bar 컴파일이 실패하지 않습니다.** 세션 시작과 동시에 `npm install -g`가 돌면 npm이 내용이 같은 `SpragBar.swift`를 다시 쓰고 swiftc는 "was modified during the build"로 실패했습니다. 이제 소스를 사본으로 옮겨 컴파일합니다. ([#21](https://github.com/rootstudioyaml/sprag/issues/21))
- **다시 하면 되는 컴파일 실패는 다음 세션에서 바로 재시도합니다.** 지금까지는 어떤 실패든 24시간 동안 다시 컴파일하지 않아 메뉴 막대가 하루 내내 비어 있었습니다. 소스가 바뀌었거나 잠깐 사라져서 실패한 경우는 이 제한에서 뺐습니다.
- **컴파일이 막혀 있으면 세션 시작 때 알려 줍니다.** 남은 시간과 바로 고치는 명령 `sprag bar build --then-launch`를 한 줄로 안내합니다. 이전에는 `sprag bar status`를 직접 열어야 알 수 있었습니다.
