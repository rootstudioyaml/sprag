## The gauge is a row of countable ticks

Adjacent full cells fuse into one shape, and a shape carries no quantity you can read off it. Twelve separate ticks do.

The six-cell bar subdivided its boundary cell into eighths for sub-cell precision, and that precision had no reader: every chip that draws a gauge prints the exact percentage immediately after it. The bar's job is the glance.

* `▰▱` is the shape, but JetBrains Mono ships neither character — verified through its cmap, U+25B0 and U+25B1 absent where U+25A0 and U+25A1 are present. A missing glyph is drawn by a fallback font whose advance width does not match the cell grid, which is the whole reason `narrow` mode exists, so narrow draws the same bar as `■□`.
* Two readings are reserved, because they are the two that change a decision. A full row means the limit is reached, so nothing below 100% draws one; anything above zero draws at least one tick, so "barely started" never looks like "untouched". The old bar had the same defect at the top — 99% already drew a full row.
* `sprag litellm-budget` follows the same resolver. It is the one path that draws a gauge in text mode, where the statusline draws none, so it would otherwise have emitted `▰▱` to a terminal chosen for lacking those glyphs.

## A finished delegation refreshes the figure immediately

`🔀 Routing saved` reads a cached scan, and the gate in front of that scan held a fresh delegation back an hour at best and a day at worst. The two figures side by side made the lag obvious: `📄 Doc2md saved` appears at once because the conversion writes its ledger entry in the same call stack.

The gate's own reasoning is what justifies the exemption. It exists because a scan over unchanged transcripts is deterministic — same input, same numbers — so running it again buys nothing. A finished delegation is the one event guaranteed to change them, and its transcript is nowhere near the 5MB the byte clause wants, so the gate treated the one certain change as a trickle.

Measured before deciding: a scan is 0.5s over the default 14-day window (67MB, 493 episodes), 0.95s over 90 days, and delegations run about 1.6 times a day. Under a second a day. A `PostToolUse` hook on `Task`/`Agent` kicks the same detached refresh session start already uses, with a 30-second floor so a fan-out of parallel agents triggers one scan rather than one per agent.

## The upgrade offer says what the new version adds

Naming two version numbers and asking whether to upgrade is not a question anyone can answer. The reason to upgrade is in what changed.

* The registry cannot supply it — `/latest` returns package metadata and no changelog — so the notes come from the release for that tag. Unauthenticated reads are 60/hour against a once-a-day check, and the request rides the same detached pass as the version lookup.
* Release bodies are written for a web page: headings, several sentences per item, markdown runs, links. The notice keeps the first sentence of each bullet, strips the markup, and takes at most three.
* Notes are optional throughout. A release written as prose yields no bullets, an unreleased tag 404s, a rate limit refuses: each costs the notes and never the notice, which is still worth showing with a bare version number.

Which makes a release with no body a user-visible defect. `npm run release:notes <version>` extracts that version's changelog section into a draft, prints the three lines the offer would show, and `--publish` creates or updates the release from it. `docs/RELEASING.md` carries the procedure.

## A fresh install can register the presets in one answer

Eleven presets asked one at a time is eleven prompts before the user reaches their own work. `seed accept all --global` already existed; the guidance hid it, telling the model not to offer the whole set and mentioning the bulk command only in a trailing parenthesis. Four choices are now offered in order: all globally, all for this project, one at a time, none.

## Fixes

* **Runs whose model id is still being learned no longer look like a fault.** Behind a gateway the id arrives as an opaque profile ARN, and the mapping is learned from observed runs — which takes a few before it can conclude anything. Below that threshold `🔀 2 unresolved` in yellow made a fresh install look broken. The chip now waits for the same threshold the learning uses.
* **Three tests that read the developer's machine are isolated.** One of them shipped v3.45.0 with CI red on all six combinations; another printed the machine's own credentials into an assertion diff when it failed.
* The budget chip is a spending limit, so it gets a card rather than a key. Gateway budgets count down in days and hours. Figures are grouped by the timeframe they cover, and a window label joins the two chips it measures.
