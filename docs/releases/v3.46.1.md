- **`uninstall` no longer takes other tools' hooks with it.** Hooks were removed a
  matcher group at a time rather than one hook at a time, and Claude Code merges
  hooks that share a matcher into one group — so a tool installed before this one
  commonly sat in the same group and disappeared with it.
- **Install and every printed command name the package you installed.** The
  statusline entry, the hooks, and the preset and uninstall guidance all said
  `claude-token-saver`; the package is `sprag-cli`, and the name now comes from one
  definition rather than eighteen string literals.
- **Recognising our own entries reads the executable, not the whole string.**
  `sprag` is five characters, so a substring test claimed anyone's
  `sprag-probe.mjs` or `my-sprag-wrapper` — and `uninstall` deletes what that test
  claims.

## Details

### uninstall removed whole matcher groups

Measured on a settings file holding one of our hooks, a probe script, and an
unrelated tool in a single `SessionStart` group: `uninstall` left nothing behind.
The unrelated `some-other-tool --init` was gone, and its name has nothing to do
with ours — the group was the unit of deletion, so everything in it went.

A group is now deleted only once nothing of anyone else's is left in it, and the
hooks inside it are filtered individually. Two tests pin it: foreign entries
sharing a group survive, and ours in that same group are still removed (otherwise
the first assertion would pass by doing nothing).

### The name had eighteen definitions

Every command string a user is expected to type or read carried the old name as a
literal. `src/cli-name.js` holds it once now, with the reason it is not the same
thing as the on-disk identifiers: the state directory, the harness block markers,
and the skill directory keep the old spelling on purpose. Renaming those would
orphan existing ledgers and stop the markers matching text already committed in
users' `CLAUDE.md`. Those are addresses, and an address only has to be stable.

Entries already on disk carry the old name, so recognition accepts both. Narrowing
it would make install miss an existing hook and add a second one beside it.

### Substring matching over-claimed, and uninstall acts on the claim

`node ~/.claude/probe/sprag-probe.mjs` and `my-sprag-wrapper --run` both matched.
The executable is now taken as the last path segment of the first token — or the
token after `npx`, `bunx`, or `pnpm dlx` — and matched whole, so a legitimate
wrapped invocation (`npx sprag-cli brief --hook`, `/usr/local/bin/sprag doc2md`)
is still recognised while a coincidental mention is not. Thirteen cases are pinned.

### The release gate had stopped gating

Renaming the draft marker to `REVIEW` left `deploy.mjs` searching for
`<!-- TRANSLATE`, which exists nowhere. A gate that greps for an absent string
does not fail — it passes, and publishes an unreviewed draft as the release. The
marker has one definition now, and one of the tests executes the drafting path
rather than only reading the source, because the source-level check passes on a
file that throws the moment it runs.

## 상세

### uninstall 이 matcher 그룹을 통째로 지웠습니다

우리 훅 하나와 프로브 스크립트, 무관한 도구를 `SessionStart` 한 그룹에 담아
실측했더니 `uninstall` 이 아무것도 남기지 않았습니다. 이름이 우리와 아무 상관이
없는 `some-other-tool --init` 까지 사라졌습니다. 삭제의 단위가 그룹이었으므로 그
안에 있던 것이 전부 함께 없어진 것입니다.

이제 그룹은 남의 항목이 하나도 남지 않을 때만 지우고, 그룹 안의 훅은 개별로
걸러냅니다. 테스트 두 건으로 고정했습니다. 같은 그룹에 있던 남의 항목이 살아남는지
확인하고, 같은 그룹의 우리 항목이 그래도 지워지는지도 확인합니다. 뒤쪽이 없으면
앞쪽 단정은 아무것도 하지 않고 통과할 수 있습니다.

### 이름이 열여덟 곳에 정의되어 있었습니다

사용자가 입력하거나 읽어야 하는 명령 문자열이 모두 옛 이름을 리터럴로 담고
있었습니다. 이제 `src/cli-name.js` 가 한 번만 정의하며, 그것이 디스크상의 식별자와
다른 이유도 함께 적었습니다. 상태 디렉터리와 harness 블록 마커, 스킬 디렉터리는
의도적으로 옛 이름을 유지합니다. 그것을 바꾸면 기존 사용자의 절감 기록이 고아가
되고, 이미 사용자의 `CLAUDE.md` 에 적혀 있는 마커와 어긋납니다. 그것들은 주소이며,
주소는 안정적이기만 하면 됩니다.

이미 디스크에 있는 항목은 옛 이름을 지니므로 인식은 양쪽을 받습니다. 좁히면 install
이 기존 훅을 못 찾아 그 옆에 하나를 더 등록합니다.

### 부분 문자열 검사가 과하게 판정하고, uninstall 이 그 판정대로 지웁니다

`node ~/.claude/probe/sprag-probe.mjs` 와 `my-sprag-wrapper --run` 이 둘 다
일치했습니다. 이제 첫 토큰의 마지막 경로 조각을 실행 파일로 보고 통째로 대조하며,
`npx`·`bunx`·`pnpm dlx` 뒤의 토큰도 같은 방식으로 봅니다. 그래서 정당한 래퍼 호출
(`npx sprag-cli brief --hook`, `/usr/local/bin/sprag doc2md`)은 그대로 인식하고,
우연한 언급은 인식하지 않습니다. 열세 가지 경우를 테스트로 고정했습니다.

### 릴리스 게이트가 게이트 역할을 하지 못하고 있었습니다

초안 표지를 `REVIEW` 로 바꾸면서 `deploy.mjs` 가 어디에도 없는 `<!-- TRANSLATE` 를
찾게 되었습니다. 없는 문자열을 grep 하는 게이트는 실패하지 않습니다. 통과하고,
미검토 초안을 릴리스로 게시합니다. 이제 표지는 한 곳에서 정의되며, 테스트 하나는
소스를 읽는 데 그치지 않고 초안 생성 경로를 실제로 실행합니다. 소스 수준 검사는
실행하는 순간 예외를 던지는 파일에서도 통과하기 때문입니다.
