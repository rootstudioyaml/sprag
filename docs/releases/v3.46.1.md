- **`install` writes the canonical command name.** Every statusline and hook entry it registers now invokes `sprag` rather than the legacy `claude-token-saver`.

---

## Why it mattered even though both names work

Both binaries ship in the package, so an entry naming either one runs the same
code — nothing was broken. But the package is `sprag-cli`, and a fresh install was
writing `claude-token-saver` into the user's `settings.json`: a name they never
typed, in a file they read.

The reverse direction is not symmetrical, and getting that wrong would have been
the real bug. Entries already on disk carry the old name, so anything that
recognises our own work has to accept both. Narrowing those checks to the new name
would make `install` miss an existing hook and register a second one beside it.
Both directions are pinned by tests now: a fresh install writes only `sprag`, and
an existing legacy entry is recognised rather than duplicated.

## 한국어

- **`install` 이 정식 명령 이름을 씁니다.** 등록하는 statusline 과 훅 항목이 모두 레거시 이름 `claude-token-saver` 대신 `sprag` 를 호출합니다.

### 두 이름이 다 동작하는데도 고친 이유

두 바이너리가 함께 배포되므로 어느 이름을 적어도 같은 코드가 돌고, 고장 난 것은 없었습니다. 다만 패키지 이름은 `sprag-cli` 인데 새 설치가 사용자의 `settings.json` 에 `claude-token-saver` 를 적고 있었습니다. 사용자가 직접 적지 않은 이름이 자기가 읽는 파일에 들어가 있는 상태였습니다.

반대 방향은 대칭이 아니고, 그쪽을 잘못 고치면 실제 결함이 됩니다. 이미 설치된 항목은 옛 이름으로 적혀 있으므로, 우리 것을 알아보는 검사는 두 이름을 모두 받아야 합니다. 그 검사를 새 이름으로 좁히면 `install` 이 기존 훅을 못 찾아 옆에 하나를 더 등록합니다. 두 방향을 각각 테스트로 고정했습니다. 새 설치는 `sprag` 만 쓰고, 기존 레거시 항목은 중복 등록되지 않고 인식됩니다.
