- **Model aliases now come straight from the LiteLLM gateway.** `GET /model/info` already knows which profile ID maps to which model, so sprag reads that mapping instead of waiting for delegation stats to accumulate or having you hand-edit `profile-map.json`. Inspect the cached mapping with `sprag profile-map` and refresh it with `sprag profile-map --refresh`; gateways that block the endpoint keep using the existing vote-based learning.
- **Learning now reads your most recent sessions.** `learnProfileMapping` took the first 40 entries of the list returned by `discoverSessionFiles`, which is ordered oldest-first, so on machines with more sessions than that the recent window was cut away entirely and profiles that only appeared lately stayed unresolved forever. In the case that surfaced this, 95 sessions fell inside 14 days, the last three days were dropped, and 18 delegations went missing from the savings total.
- **`profile-map.json` is merged per section instead of rewritten whole.** The learning path and the gateway refresh each rewrote the entire file and could erase the other's section. Each writer now re-reads the file and merges only its own keys, and writes through a temporary file it then renames, so an interrupted write can no longer turn hand-written `modelAliases` into a parse error.
- **A stale gateway mapping steps aside for learned values.** Preferring the gateway's declaration over learned votes only holds while that declaration is current, so a table that has not refreshed in more than 14 days yields and the learned result answers instead.
- No auth token is stored. Every call reads whatever token `apiKeyHelper` holds at that moment and keeps no copy of it.
- The unresolved notice in `sprag route-scan` now points at `profile-map --refresh` before suggesting a manual edit.

## 한국어

- **LiteLLM 게이트웨이에서 모델 별칭을 즉시 받아 옵니다.** 게이트웨이가 `GET /model/info` 로 이미 알고 있는 프로파일 ID와 모델명의 대응을 그대로 읽어 오므로, 위임 통계가 쌓이기를 기다리거나 `profile-map.json` 을 손으로 편집할 필요가 없어졌습니다. `sprag profile-map` 으로 캐시된 매핑을 확인하고 `sprag profile-map --refresh` 로 갱신합니다. 이 경로가 막힌 게이트웨이에서는 기존 투표 학습이 그대로 동작합니다.
- **학습이 최근 세션을 읽습니다.** `discoverSessionFiles` 가 오래된 순으로 돌려주는 목록을 `learnProfileMapping` 이 최근 순으로 가정하고 앞 40개만 읽고 있었습니다. 세션이 그보다 많은 환경에서는 최근 구간이 통째로 잘려 나가 최근에만 등장한 프로파일이 영구히 미해석으로 남았습니다. 실측 사례에서는 14일 안에 세션 95개가 있었고 최근 사흘이 버려져 위임 18건이 절감 집계에서 빠졌습니다.
- **`profile-map.json` 이 절 단위로 갱신됩니다.** 학습 경로와 게이트웨이 갱신이 각각 파일 전체를 다시 쓰면서 서로의 절을 지울 수 있었습니다. 이제 쓰기 직전에 파일을 다시 읽어 자기 키만 병합하며, 임시 파일에 쓰고 이름을 바꾸므로 쓰기가 중단되어도 손으로 적어 둔 `modelAliases` 가 파싱 오류로 사라지지 않습니다.
- **오래된 게이트웨이 매핑은 학습값에 자리를 내줍니다.** 게이트웨이 선언을 학습 투표보다 우선하는 근거는 그 선언이 현재 값일 때만 성립합니다. 갱신이 14일 넘게 막힌 표는 물러나고 학습 결과가 답합니다.
- 인증 토큰은 저장하지 않습니다. 호출 시점마다 `apiKeyHelper` 가 보유한 토큰을 그대로 읽어 쓰고 사본을 남기지 않습니다.
- `sprag route-scan` 의 unresolved 안내가 수동 편집 대신 `profile-map --refresh` 를 먼저 권합니다.
