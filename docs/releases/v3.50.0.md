- **The effort chip now wears Claude Code's own colors for the effort levels.** Picking a level in one UI and reading it back in another meant learning the same value twice, so this release drops the palette of its own devising and transcribes the app's: yellow at `low`, green at `medium`, blue at `high`, purple at `xhigh`, and the rainbow spread across the word at `max`. The source is Claude Code's effort slider table, whose rows name the semantic color keys `warning`, `success`, `permission`, `autoAccept` and `rainbow`. The chip follows your `theme` setting across all six themes, including the daltonized pair, and falls back to the app's ANSI themes on terminals without 24-bit color.
- **`ultracode` is now told apart from `xhigh`.** `/effort ultracode` is xhigh plus dynamic workflow orchestration, but only the xhigh half reaches the statusline payload, so the two states used to look identical. The chip now recovers the difference from the session transcript, taking whichever is later: the `/effort` command's own output, or the ultracode system-reminder. The command output is written the moment the command returns, so the chip does not wait for the next turn to catch up.
- ultracode is drawn as a purple glow. Claude Code separates it from `xhigh` by shimmering one of them, and a statusline cannot animate — it re-runs on an interval measured in seconds, each run a fresh process with no frame state. So the shimmer's two endpoints are spread across the letters instead of cycled over time, brightening toward the middle. `max` takes the same treatment for its rainbow.
- Reading the transcript is bounded. The file is opened only when the payload says `xhigh`, since that is the only level ultracode can present as, and the scan covers the last 4MB walking backwards. Real sessions put at most 2.2MB between two ultracode reminders, so that leaves room; past the bound the chip reports `xhigh`, which is what it showed before this existed. The detection can therefore only under-report, never invent.
- A line that merely quotes a command's output does not count. The phrase `Set effort level to …` also travels through tool output and answer text, so only a user entry whose content is a plain string carrying the `<local-command-stdout>` wrapper is accepted. Measured against one session, that filter excluded all six quoted occurrences and kept all twelve real ones.
- **`npm run deploy` no longer releases whichever version the clone happens to hold.** The version to release came from CHANGELOG.md, and that file was read before `git pull`, so a checkout sitting behind origin resolved the release it had already shipped: its tag was present, npm already served it, the publish was skipped, and the run reported the old version as though there were nothing to do. Nothing about that looks like a failure, and the Slack bot's clone is long-lived while the pushes arrive from elsewhere, so it answered nearly every deploy request that way. The pull now runs first and brings tags with it, and the run says which of the two no-op cases it is in.
- The statusline gauge test no longer depends on the terminal it runs in. It pinned the legacy bright-black escape while the palette emits 24-bit slate wherever `COLORTERM` advertises truecolor, so it passed in CI, where the variable is unset, and failed on the machines releases are actually run from. `npm run deploy` runs the suite before it publishes, so that mismatch blocked the release as well.
- sprag.io now carries the reference documentation as pages of its own, generated from `docs/` when the site deploys. The statusline, routing, harness, doc2md, gateway, install, command and Korean-style pages are there in English, and in Korean wherever a translation exists.

## 한국어

- **effort 칩이 Claude Code 와 같은 색을 씁니다.** 레벨을 고른 화면과 칩이 서로 다른 색을 보여 주면 같은 값을 두 번 배우게 되므로, 자체 배색을 버리고 Claude Code 의 값을 그대로 가져왔습니다. `low` 는 노란색, `medium` 은 녹색, `high` 는 하늘색, `xhigh` 는 보라색이고 `max` 는 무지개 일곱 색을 글자마다 나누어 칠합니다. 근거는 Claude Code 의 effort 슬라이더 표이며 색 키가 `warning`·`success`·`permission`·`autoAccept`·`rainbow` 로 적혀 있습니다. `theme` 설정을 읽어 여섯 테마(기본 `dark`, `light`, 색약 대응 둘, ANSI 둘)를 따라가고, 24비트 색이 없는 터미널에서는 Claude Code 의 ANSI 테마 값으로 떨어집니다.
- **`ultracode` 를 xhigh 와 구분해 보여 줍니다.** `/effort ultracode` 는 xhigh 에 동적 워크플로 오케스트레이션을 더한 설정인데 statusline 페이로드에는 `xhigh` 로만 도착하므로, 예전에는 두 상태가 똑같이 보였습니다. 이제 세션 트랜스크립트에서 `/effort` 명령의 출력과 ultracode 알림 중 나중에 기록된 쪽을 읽어 `🔬 ultracode` 로 표시합니다. 명령 출력은 명령이 응답한 즉시 기록되므로 다음 턴을 기다리지 않습니다.
- ultracode 는 보라색 glow 로 그립니다. Claude Code 는 xhigh 를 반짝여서 두 레벨을 구분하는데 statusline 은 초 단위로 다시 실행되고 매번 새 프로세스라 애니메이션을 만들 수 없습니다. 그래서 반짝임의 두 끝값을 시간이 아니라 글자 위에 펼쳐, 가운데로 갈수록 밝아지게 했습니다. `max` 의 무지개도 같은 방식입니다.
- 트랜스크립트를 읽는 비용에는 상한을 두었습니다. 페이로드가 `xhigh` 라고 말할 때만 파일을 열고, 끝에서 4MB 안쪽만 역방향으로 훑습니다. 실제 세션에서 알림 간격이 최대 2.2MB 였으므로 여유가 있고, 범위를 넘어가면 예전처럼 `xhigh` 로 표시합니다. 판정을 틀리는 방향이 한쪽으로만 열려 있습니다.
- 명령 출력을 인용한 줄은 세지 않습니다. `Set effort level to ...` 라는 문구는 도구 출력이나 답변 본문에도 실릴 수 있어서, 사용자 엔트리이고 본문이 문자열이며 `<local-command-stdout>` 표지를 가진 줄만 인정합니다. 이 조건으로 한 세션에서 인용 6건을 모두 걸러 내고 실제 명령 출력 12건을 모두 남겼습니다.
- **`npm run deploy` 가 클론에 남아 있던 옛 버전을 릴리스하지 않습니다.** 릴리스할 버전을 CHANGELOG.md 에서 읽는데 그 읽기가 `git pull` 보다 앞에 있었습니다. 그래서 origin 보다 뒤처진 체크아웃은 이미 배포한 버전을 골랐고, 태그도 있고 npm 에도 있으니 publish 를 건너뛴 채 옛 버전을 다 나간 것으로 보고했습니다. 이 종료는 실패처럼 보이지 않습니다. 슬랙 봇의 클론은 오래 살아 있고 푸시는 다른 곳에서 들어오므로 거의 모든 배포 요청이 이렇게 끝났습니다. 이제 pull 을 먼저 하고 태그도 함께 받으며, 실제로 할 일이 없는 두 경우 중 어느 쪽인지 줄로 남깁니다.
- statusline 게이지 테스트가 실행되는 터미널에 좌우되지 않습니다. 팔레트는 `COLORTERM` 이 truecolor 를 알리는 곳에서 24비트 회색을 내보내는데, 테스트는 옛 8색 코드를 고정해 두었습니다. 그래서 변수가 비어 있는 CI 에서는 통과하고 정작 릴리스를 돌리는 기기에서는 실패했습니다. `npm run deploy` 는 publish 전에 테스트를 돌리므로 이 어긋남도 배포를 막았습니다.
- sprag.io 에 참고 문서가 개별 페이지로 올라갑니다. 사이트를 배포할 때 `docs/` 원본에서 생성하며, statusline·라우팅·harness·doc2md·게이트웨이·설치·명령어·한국어 문체 페이지를 영어로 싣고 번역이 있는 문서는 한국어로도 싣습니다.
