- **The statusline's cache-savings figure is priced per session, at that session's model.** Every token in the window used to be priced at the first session in the list, and the list is sorted by modification time, so the session touched longest ago set the rate: a short haiku scratch session made a day of Fable work look about a tenth as valuable. Each session is now priced at its own model and the results summed. In write-heavy sessions where the figure would go negative, the chip floors at zero instead of showing `$-0.42`.
- **Removing our hook no longer removes another tool's hook from the same group.** `hook-manager` filtered out any PostToolUse group that contained one of our hooks. Claude Code merges hooks with the same matcher into one group, so a tool installed before us lost its hook. Removal is now per entry, a group survives while someone else's hook is in it, and a `PostToolUse` that is not an array is left alone with a notice rather than overwritten with an empty list.
- **The statusline no longer reads the current session's transcript from the start on every refresh.** Finding the last user prompt streamed the whole file, which on a 65MB session meant re-reading it every five seconds. The tail is now read backwards in 64KB chunks up to 4MB, and the full scan runs only when no user entry lies within that range.
- Korean acknowledgements (`계속`, `응`, `네`, `진행`) were never excluded from delegation counting. The pattern ended each one with `\b`, which in JavaScript is ASCII-only and never matches after a Hangul syllable; a lookahead for whitespace or end of text replaces it.
- The delegation ledger credited a rule with runs that predate its promotion. Runs were matched to rules by tier and category alone, so a rule promoted today claimed the previous two weeks of runs. A run now counts only when it started after the rule's `promotedAt`; registries without that date behave as before.
- The prompt-time hint regexes were tightened. `왜` escalates only when followed by a space or question mark, and `릴리즈` only when it is not `릴리즈 노트`. `되게` and `되도록` count as implementation only in the causative shape (`되도록 하자`), so the intensifier in `되게 느린데` no longer silences a hint. A text over 400 characters is treated as a paste only when it has eight or more lines or the shape of a log or stack trace; a long written spec stays quiet. Across 1,282 prompts, hints fell from 397 to 371 with none added.
- `sprag mode text` and `narrow` now apply to the installed statusline. The install command carries `--icon`, and the flag outranked the stored choice; it now decides only when nothing is stored.
- Smaller fixes. A numeric `autoCompactWindow` of `200` reads as 200k like the string `"200"`. The caps cache and harness state are written to a temporary file and renamed so the statusline never reads a truncated file. The PostToolUse hook hands its parsed entries to the analyzer instead of re-reading the transcript, records the most frequent model with `<synthetic>` skipped, and trims `cache-stats.jsonl` to its last 2,000 lines once it passes 5MB. `npm view`, `gh auth token` and the release lookup in the deploy scripts carry timeouts. Path separators are normalized so Windows pnpm, bun and yarn installs are not reported as npm. The promoted-rule template no longer writes an em dash, the install prompt describes the real default lint scope, and the `korean` status line names Bash among the hooked tools.

## 한국어

- **statusline 의 캐시 절감액을 세션마다 그 세션의 모델 단가로 계산합니다.** 창 안의 모든 토큰을 목록 첫 세션의 모델로 매겼는데, 목록은 수정 시각 오름차순이라 가장 오래 전에 건드린 세션이 단가를 정했습니다. haiku 로 잠깐 쓴 세션이 하루치 Fable 작업의 단가가 되면 절감액이 약 10분의 1로 줄어 보였습니다. 이제 세션별로 계산해 합칩니다. 절감액이 음수가 되는 쓰기 위주 세션에서는 `$-0.42` 대신 0 으로 바닥을 둡니다.
- **훅을 지울 때 같은 그룹에 있던 다른 도구의 훅을 함께 지우지 않습니다.** `hook-manager` 는 그룹 안에 우리 훅이 하나라도 있으면 PostToolUse 그룹 전체를 걸러 냈습니다. Claude Code 는 matcher 가 같은 훅을 한 그룹으로 합치므로, 우리보다 먼저 설치된 도구의 훅이 사라졌습니다. 이제 항목 단위로 지우고, 다른 도구의 훅이 남아 있으면 그룹을 유지합니다. `PostToolUse` 가 배열이 아니면 빈 배열로 덮어쓰지 않고 그대로 두고 알립니다.
- **statusline 이 현재 세션의 트랜스크립트를 매번 처음부터 읽지 않습니다.** 마지막 사용자 프롬프트 시각을 찾으려고 세션 파일 전체를 스트리밍했는데, 65MB 세션에서는 5초마다 파일 하나를 통째로 다시 읽는 비용이었습니다. 이제 파일 끝에서 64KB 씩 최대 4MB 까지 거꾸로 읽고, 그 안에 사용자 항목이 없을 때만 전체 스캔으로 내려갑니다.
- 한국어 응답 표지(`계속`, `응`, `네`, `진행`)가 위임 후보 집계에서 빠지지 않고 있었습니다. 표지 뒤에 `\b` 를 두었는데 JS 의 `\b` 는 ASCII 전용이라 한글 뒤에서는 절대 맞지 않습니다. 공백이나 문장 끝을 보는 lookahead 로 바꾸었습니다.
- 위임 절감 원장이 룰을 승격한 날짜 이전의 실행까지 그 룰의 성과로 적었습니다. 룰은 티어와 카테고리만으로 실행과 짝지어졌으므로, 오늘 승격한 룰이 지난 2주의 실행을 모두 가져갔습니다. 이제 실행 시작 시각이 승격일 이후일 때만 인정합니다. 승격일이 없는 예전 레지스트리는 이전과 같이 동작합니다.
- 프롬프트 시점 힌트의 정규식을 손봤습니다. `왜` 는 뒤에 공백이나 물음표가 올 때만, `릴리즈` 는 `릴리즈 노트` 가 아닐 때만 상위 모델로 올립니다. `되게`·`되도록` 은 `되도록 하자` 같은 사동 꼴일 때만 구현 요청으로 보고, `되게 느린데` 같은 강조 부사는 힌트를 막지 않습니다. 400자를 넘는 글은 줄이 8개 이상이거나 로그·스택 트레이스 모양일 때만 붙여넣기로 보고, 길게 쓴 요청 사양은 조용히 넘어갑니다. 1,282건 프롬프트에서 힌트 397건이 371건으로 줄었고 새로 생긴 힌트는 없습니다.
- `sprag mode text` 와 `narrow` 가 설치된 statusline 에 적용됩니다. 설치 명령에 `--icon` 이 들어 있어 저장된 선택보다 플래그가 앞섰습니다. 이제 저장된 선택이 없을 때만 플래그가 결정합니다.
- 작은 정리 몇 가지입니다. `autoCompactWindow` 를 숫자 `200` 으로 적어도 문자열 `"200"` 과 같이 200k 로 읽습니다. 한도 캐시와 harness 상태 파일은 임시 파일에 쓴 뒤 이름을 바꾸어 statusline 이 잘린 파일을 읽지 않습니다. PostToolUse 훅은 파싱한 항목을 분석기에 넘겨 트랜스크립트를 두 번 읽지 않고, `<synthetic>` 을 건너뛴 최다 모델을 기록하며, `cache-stats.jsonl` 은 5MB 를 넘으면 뒤쪽 2,000줄만 남깁니다. 배포 스크립트의 `npm view`, `gh auth token`, 릴리스 조회에 타임아웃을 두었습니다. Windows 에서 pnpm·bun·yarn 설치를 npm 으로 잘못 안내하던 경로 구분자 처리를 고쳤습니다. 승격 룰 템플릿의 em dash, 설치 안내의 검사 범위 설명, `korean` 상태 줄의 훅 대상(Write·Edit·Bash)을 실제와 맞췄습니다.
