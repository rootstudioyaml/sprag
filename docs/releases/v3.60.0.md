- **The statusline shows when a counter was reset and which subagents this session ran.** After `sprag saved reset` the savings figures carry their start date (`since 10/9`), and a zero stays visible as `$0.00 since 10/9` instead of vanishing. The subagents this session started are counted by model family (`🔀 this session 3 (haiku 2 · sonnet 1)`), and `scan 3d` appears beside the routing figure when the last `route-scan` is more than three days old. When several 🅷 warnings are due, the highest is named and the rest are counted (`🅷⚠ PEV-skip +2`) so a lower one is no longer hidden. Verbose mode shows how long ago updates were checked (`v3.59.0 ✓6h`), and `--segments rules` adds the number of rules in force and how many need review (`rules 10 · ⚠1`).
- **An English reply to a Korean prompt is sent back for a Korean answer before the turn ends.** The model sometimes answered a Korean prompt in English, usually right after a stretch of English work such as commit messages or release notes. A new Stop hook, `sprag korean --reply-hook`, blocks a turn whose prompt is Korean and whose reply is English and asks for the answer again in Korean. Code blocks, paths and URLs are not counted, and a prompt containing `영어로` or `in English` is not checked. On 14 days of transcripts, 2,204 Korean-prompt turns produced 8 flags, all 8 real English replies. Users with the Korean style enabled get the hook on upgrade, and `sprag korean reply off` turns it off.
- **New releases are noticed sooner.** Update checks ran once a day, so three releases that shipped a few hours after a check stayed unseen until the next day. SessionStart now checks on a 3-hour interval (the statusline keeps 24 hours), and a running version newer than the cached latest counts as a fresh upgrade and triggers a re-check at once. A downgrade, or a second copy rendering alongside, does not.
- Routing: a question about how the tool works no longer gets a command-running hint because of one weight-1 keyword such as 설치 ("install"); scan statistics are unchanged. Per-rule savings count only runs after the routing reset, while run counts and error rates keep the whole window for rule health, and `saved reset` and `undo` rescan so `ratchet-model.md` follows at once.
- A failed state-file write now removes its temp file, and a once-a-day sweep deletes `<state>.json.<pid>.tmp` files older than an hour. Codex panel frame and hook files older than seven days are swept once a day, keeping the current session's.
- `sprag compact-window` judges the window the same way the statusline does. The command runs outside a session and decided 1M from the settings model id alone, so a user running Opus 5.5 as a bare `opus` (no `[1m]`) saw 1M on the statusline and "200k context" from the command. It now uses the window the statusline last reported and prints that figure next to the verdict.
- README and sprag.io gain a table linking each tier criterion to the routing papers behind it (RouteLLM, FrugalGPT, RouterArena and others). The 28% vs 54% and +63pp figures are marked as sprag's own offline measurement, and the two criteria with no paper behind them say so.
- The deploy script finishes the global reinstall. On the last three releases its 120-second wait ran out before the registry served the new version, so the reinstall never ran. It now waits up to six minutes, asks the registry with `--prefer-online`, and runs `sprag install` itself afterwards because npm 11 skips postinstall under allow-scripts. Statusline captures for the docs no longer include the compact-window chip that depends on the capturing machine's settings.

## 한국어

- **상태줄이 초기화 시점과 이번 세션의 서브에이전트를 보여 줍니다.** `sprag saved reset` 을 실행한 뒤에는 절감 금액에 `since 10/9` 처럼 기준일이 붙고, 합계가 0이어도 사라지지 않고 `$0.00 since 10/9` 로 남습니다. 이번 세션이 실행한 서브에이전트 수를 모델 계열별로 `🔀 this session 3 (haiku 2 · sonnet 1)` 처럼 보여 주며, 마지막 `route-scan` 이 3일보다 오래되면 금액 옆에 `scan 3d` 가 붙습니다. 🅷 경고가 여럿이면 가장 높은 하나 옆에 나머지 개수를 붙여(`🅷⚠ PEV-skip +2`) 낮은 경고가 가려지지 않게 했습니다. verbose 에서는 마지막 업데이트 확인 이후 지난 시간(`v3.59.0 ✓6h`)이 나오고, `--segments rules` 로 적용 중인 룰 수와 재검토 대상 수(`rules 10 · ⚠1`)를 켤 수 있습니다.
- **한국어 질문에 영어로 답하면 턴이 끝나기 전에 다시 답하게 합니다.** 커밋 메시지나 릴리스 노트처럼 영어 작업을 길게 한 직후에 모델이 한국어 질문에 영어로 답하는 경우가 있었습니다. 새 Stop 훅 `sprag korean --reply-hook` 이 질문이 한국어이고 답변이 영어인 턴을 막고 한국어로 다시 답하게 합니다. 코드 블록과 경로, URL은 세지 않고, 질문에 `영어로` 나 `in English` 가 있으면 검사하지 않습니다. 14일치 대화 기록의 한국어 질문 2,204턴에서 8건이 걸렸고 8건 모두 실제 영어 답변이었습니다. 한국어 문체를 켜 둔 사용자는 업그레이드할 때 훅이 함께 설치되며, `sprag korean reply off` 로 끌 수 있습니다.
- **새 릴리스를 더 빨리 알립니다.** 업데이트 확인은 24시간에 한 번이라, 확인 직후 몇 시간 뒤에 나온 릴리스 세 개가 다음 날까지 보이지 않았습니다. 이제 세션 시작 때는 3시간 간격으로 확인하고(상태줄은 24시간 그대로), 실행 중인 버전이 캐시에 기록된 최신 버전보다 새로우면 업그레이드 직후로 보고 바로 다시 확인합니다. 다운그레이드했거나 다른 사본이 함께 그려지는 경우에는 다시 확인하지 않습니다.
- 라우팅: 도구가 어떻게 동작하는지 묻는 설명 질문이 '설치' 같은 가중치 1짜리 단어 하나 때문에 명령 실행 위임 안내를 받던 문제를 고쳤습니다. 스캔 통계는 그대로입니다. 룰별 절감액은 라우팅 초기화 시점 이후의 실행만 합산하고, 실행 수와 실패율은 룰 건강도 판정을 위해 전체 구간을 유지합니다. `saved reset` 과 `undo` 는 바로 다시 스캔해 `ratchet-model.md` 에 즉시 반영합니다.
- 상태 파일을 쓰다가 실패하면 남은 임시 파일을 지우고, 하루 한 번 한 시간 넘게 남은 `<state>.json.<pid>.tmp` 파일을 정리합니다. Codex 패널의 프레임 파일과 훅 파일도 7일이 지나면 하루 한 번 정리하되, 현재 세션의 파일은 남깁니다.
- `sprag compact-window` 가 상태줄과 같은 창 크기로 판정합니다. 이 명령은 세션 밖에서 실행되므로 설정의 모델 id만 보고 1M 여부를 판정했습니다. 그래서 `[1m]` 이 붙지 않은 `opus` 로 Opus 5.5를 쓰는 사용자에게 상태줄은 1M을 보여 주는데 이 명령은 "200k context"라고 출력했습니다. 이제 상태줄이 마지막으로 알린 창 크기를 쓰고, 그 값을 판정 옆에 함께 보여 줍니다.
- README와 홈페이지에 티어 판별 기준마다 근거가 된 라우팅 논문(RouteLLM, FrugalGPT, RouterArena 등)을 잇는 표를 넣었습니다. 28% 대 54%, +63pp 수치는 sprag 자체 오프라인 측정임을 밝혔고, 논문 근거가 없는 기준 두 개도 그렇다고 적었습니다.
- 배포 스크립트가 전역 재설치까지 마칩니다. 최근 세 번의 배포에서 레지스트리가 새 버전을 내주기 전에 120초 대기가 끝나 전역 재설치가 실행되지 않았습니다. 이제 최대 6분을 기다리며 `--prefer-online` 으로 레지스트리에 묻고, npm 11이 allow-scripts 때문에 postinstall을 건너뛰므로 재설치 뒤 `sprag install` 을 직접 실행합니다. 문서용 상태줄 캡처에는 캡처하는 머신의 설정에 따라 붙는 compact-window 칩이 들어가지 않습니다.
