- **`sprag` opens with the routing summary, even before anything is installed.** `npx sprag-cli@latest`, or `sprag` with no arguments, used to open with the old "Claude Token Saver" heading and go straight to token-spike warnings. It now opens with the share of the last 14 days' requests that were lookups, checks or test runs a cheaper model handles, the top three delegation candidates, and the one command that approves the first. The figures come from the route-scan cache; a first run performs the scan locally in a few seconds and writes only sprag's own cache file, nothing under `~/.claude`. `--project` skips the section, since the scan covers every project, and `CTS_NO_ROUTE_SCAN=1` skips it the way it does for the hooks. The heading reads `Sprag — Last N days`.
- **The delegation subagents pin their effort, and escalation moves the axis the failure calls for.** The rules chose a model tier and left effort to whatever the session inherited. Effort is a separate axis set by how the work is verified, not by how hard it is: haiku-explore, haiku-runner and haiku-translate, whose results are checked by command output or a file comparison, carry `effort: low`; sonnet-worker, which implements a fixed design against tests, carries `medium`. The main session's effort is left alone, and the rules say never to set `CLAUDE_CODE_EFFORT_LEVEL`, which overrides every subagent's own value. The escalation clause in ratchet-model.md now distinguishes an omission (a file not read, tests not run, a cap hit mid-task), which retries once on the same model with the Agent call's `effort` argument one step up, from a wrong answer reached with the full context, which moves up one tier. Agent files without sprag's ownership mark are left as they are.
- **The README, sprag.io and the npm description open with "model-delegation router".** The first line said "cut token spend", which names the outcome and hides what the tool is; someone deciding whether to install a tool that edits settings.json had nothing to go on. The first line is now "A model-delegation router for Claude Code and Codex", and the opening paragraph explains the router first: rules in the main session, sub-agents pinned to a cheaper model, rules derived from your own logs and approved one by one, a ledger entry per delegated run. Document conversion and the statusline follow, and the clutch metaphor is one paragraph. The npm keywords gain `model-router`, `model-delegation`, `llm-router` and `claude-code-router`.
- **The statusline asks for a star once, for a day, when routing and doc2md savings first reach $10.** `⭐ $12.0 saved · star github.com/rootstudioyaml/sprag` appears after the doc2md chip for 24 hours and then never again. The moment is recorded in the same first-run.json the other one-time notes use, and `CTS_NO_NOTE=1` suppresses it. The chip reuses the totals the savings chips already computed, so a render pays no second ledger read. `--segments star` names it alone.
- **Every network destination is documented.** docs/INSTALL.md and INSTALL.ko.md carry one table listing the npm registry and the GitHub releases API (the update check), the LiteLLM gateway's `/key/info`, `/user/info` and `/model/info` (the budget gauge and model map), the `gh` CLI or a Google Form (`sprag feedback`), and the npm and pip installs behind `sprag upgrade` and the doc2md converter, each with when it is contacted, what is sent and the switch that stops it. The list comes from a static scan of the published 3.68.0 package; no usage data, transcript content or project path leaves the machine.
- **A release compares the published tarball with the tag, and every shipped code file must be reachable from an entry point.** `npm run deploy` fetches the tarball back as soon as the registry serves the new version, compares every file with `git archive <tag>`, and stops before the global reinstall if any differ; 3.68.0 matched on all 157 files. `src/changelog.js` was release tooling used only by scripts/ and test/, shipped as dead code because `files` lists all of `src/`. It moves to `scripts/changelog.mjs`, and a test walks the `npm pack --dry-run` list from the bin, postinstall and mod entry points and fails on any code file the walk never reaches.
