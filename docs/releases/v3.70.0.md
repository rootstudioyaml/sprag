- **An opt-in team layer: only machines that join send anything, and what they send is one aggregate row per day.** Join with `sprag team join <token>`, or set `SPRAG_TEAM_TOKEN` in the environment to enroll an organization at the next session start. From then on a detached child of the SessionStart hook uploads, at most every 6 hours, one row per local calendar day (spend, savings, delegated-run count and model-family share) to Supabase in ap-northeast-2, and pulls the rules the team approved. Prompts, transcripts, file paths and project names are never sent, and rule text goes up only through `sprag team propose`. `sprag team status --show-payload` prints the exact rows, `sprag team leave` removes the key, the cache and the import and wins over the environment, and `CTS_NO_TEAM_SYNC=1` stops all team traffic. An install that never joins sends nothing, exactly as before.
- **Team-approved rules arrive in `~/.claude/ratchet-team.md`.** The file is re-rendered from the cache at session start and imported from the global harness block only while it exists. Codex gets `<CODEX_HOME>/ratchet-team.md` through its SessionStart hook, and the Cowork copy includes it. A machine enrolled through the environment prints a one-line notice in its first session naming the team and the two commands that show and stop the upload.
- **Owners create a team from the terminal with `sprag team create`.** After the 6-digit code from the sign-in email, the team exists, this machine joins as its first member, and the command prints the member line (`npm i -g sprag-cli@latest && sprag team join <token>`) and the `SPRAG_TEAM_TOKEN` line for an organization rollout. Without a TTY, as under an agent, it runs in two steps: `--email` sends the code and a re-run with `--code` and `--name` creates the team. Signing in to sprag.io/team with the same email shows per-member spend, savings and delegated runs for 30 days, the daily chart, rule approval and removal, member removal and invite rotation. Prompt capture is a team policy on the Business plan; this CLI does not upload prompts yet and only shows the policy flag in `sprag team status`.
- **The network table lists the team layer.** docs/INSTALL.md gains a row for the Supabase RPC endpoint with its off switch, the sentence that no usage data leaves the machine now carries the team exception, and the new docs/TEAM.md covers what is sent and what is not, individual joins, organization enrollment, rules, files and environment variables.
- **Fable sessions delegate heavy implementation to opus.** Delegation used to reach only haiku (T2) and sonnet (T1), so a Fable session had nowhere to hand work that opus-class could do, and a Fable-to-Opus subagent run booked no saving. The new tier T1H covers episodes beyond sonnet's range with at most 3 errors, at most 20 mutating calls and output at or below the 95th percentile of your own distribution (clamped to 15000-60000 tokens, 30000 while the sample is small); judgement keywords, no category and already-delegated episodes still go to T0 first. The rule fires only in Fable/Mythos sessions; Opus and Sonnet sessions behave exactly as before. An `opus-worker` agent (`claude-opus-5-5`, effort high) is installed and removed with the other delegation agents, and a category's haiku, sonnet and opus rules merge into one line. On Codex, the most expensive of three or more cheaper models resolves to T1H automatically, and `delegate shared map T1H` sets it by hand. Production-database work and go-ahead requests such as "approved, go ahead" now count as judgement keywords, so no tier delegates them.

## 한국어

- **팀 레이어가 생겼습니다. 옵트인이며, 참여한 PC 만 하루 단위 집계를 보냅니다.** `sprag team join <토큰>` 으로 참여하거나, 조직 배포용 `SPRAG_TEAM_TOKEN` 환경변수가 있으면 다음 세션 시작 때 참여합니다. 그 뒤 SessionStart 훅이 띄운 분리 자식이 6시간에 한 번, 로컬 날짜별로 지출·절감·위임 실행 횟수·모델 계열 비중 한 줄씩을 Supabase(ap-northeast-2)에 올리고 팀이 승인한 룰을 받아 옵니다. 프롬프트·트랜스크립트·파일 경로·프로젝트 이름은 보내지 않고, 룰 본문은 `sprag team propose` 로 직접 올릴 때만 갑니다. `sprag team status --show-payload` 가 올라갈 행을 그대로 보여 주고, `sprag team leave` 는 키와 캐시와 import 를 지우며 환경변수보다 우선합니다. `CTS_NO_TEAM_SYNC=1` 은 참여 여부와 무관하게 전송을 막습니다. 참여하지 않은 설치는 이전과 똑같이 아무것도 보내지 않습니다.
- **팀이 승인한 룰이 `~/.claude/ratchet-team.md` 로 들어옵니다.** 세션 시작 때 캐시에서 다시 그리고, 파일이 있는 동안만 전역 CLAUDE.md 의 하네스 블록에 import 줄을 넣습니다. Codex 는 `<CODEX_HOME>/ratchet-team.md` 를 SessionStart 훅이 주입하고, Cowork 사본에도 함께 들어갑니다. 조직 배포로 자동 참여된 PC 는 첫 세션에 팀 이름과 확인·해제 명령을 한 줄로 안내합니다.
- **오너는 `sprag team create` 로 터미널에서 팀을 만듭니다.** 이메일로 받은 6자리 코드를 넣으면 팀이 생기고, 이 PC 가 첫 멤버로 참여하며, 멤버용 명령(`npm i -g sprag-cli@latest && sprag team join <토큰>`)과 조직 배포용 `SPRAG_TEAM_TOKEN` 줄을 출력합니다. TTY 가 없는 에이전트 환경에서는 `--email` 로 코드를 보내고 `--code`·`--name` 으로 다시 실행하는 두 단계로 동작합니다. 같은 이메일로 sprag.io/team 에 로그인하면 멤버별 30일 지출·절감·위임 횟수, 하루 단위 차트, 룰 승인·제거, 멤버 제거, 초대 토큰 교체를 할 수 있습니다. 프롬프트 수집은 비즈니스 요금제의 팀 정책이며, 이번 CLI 는 프롬프트를 올리지 않고 정책 플래그만 `sprag team status` 에 보여 줍니다.
- **네트워크 표에 팀 레이어 목적지를 더했습니다.** docs/INSTALL.md 의 표에 Supabase RPC 한 줄과 끄는 방법을 적고, "사용량 데이터는 밖으로 나가지 않는다"는 문장에 팀 참여 예외를 붙였습니다. 새 문서 docs/TEAM.md 가 보내는 것과 보내지 않는 것, 개인 참여, 조직 배포, 룰, 파일과 환경변수를 정리합니다.
- **Fable 세션은 고난도 구현을 opus 에 위임합니다.** 지금까지 위임 대상은 haiku(T2)와 sonnet(T1) 둘뿐이라, Fable 세션이 opus 급으로 충분한 큰 구현을 맡길 곳이 없었고 Fable→Opus 서브에이전트 실행에는 절감액도 잡히지 않았습니다. 새 등급 T1H 는 에러 3회 이하, 변경 20회 이하, 출력이 사용자 분포의 95번째 백분위(15000~60000 토큰으로 제한, 표본이 적으면 30000) 이하이면서 sonnet 범위를 넘는 에피소드에 붙고, 판단 키워드·카테고리 없음·이미 위임됨은 여전히 T0 가 먼저 가져갑니다. 룰은 Fable·Mythos 세션에서만 발동하고 Opus·Sonnet 세션은 이전과 똑같습니다. `opus-worker` 에이전트(`claude-opus-5-5`, effort high)가 위임 에이전트와 함께 설치·제거되며, 한 카테고리의 haiku·sonnet·opus 룰은 한 줄로 합쳐집니다. Codex 는 더 싼 모델이 셋 이상일 때 가장 비싼 쪽을 T1H 로 자동 지정하고 `delegate shared map T1H` 로 직접 지정할 수 있습니다. 운영 DB 작업과 "승인할게 진행해줘" 같은 실행 허락 요청은 어느 등급으로도 위임하지 않도록 판단 키워드에 더했습니다.
