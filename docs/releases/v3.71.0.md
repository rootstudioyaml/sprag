- **Teams now sit inside organizations, and seats are counted per organization.** A seat is one machine (one member key) active in the last 30 days, and an organization admin can merge a person's second machine into their first seat. Each organization has a seat limit, and a join past it is refused with no overage billing and no grace period. The organization owner sets the limit and appoints admins; admins create teams, assign team owners and see every team in the organization. The plan (team or business) now belongs to the organization, and only Sprag can change it.
- **`sprag team create --org <org-id>` creates a team inside an existing organization.** It calls the server's `team_create` with your sign-in session; without `--org` a new organization named after the team is created, so it behaves as in 3.70.0. The output now includes the organization name and how many seats are used (for example 1/5), and `sprag team status` shows the organization name.
- **A join refused at the seat limit now ends with a clear message and exit code 1.** The CLI maps the server's `seat limit reached` to a typed error and prints that the organization has no free seat and the Sprag admin should raise the limit, in English or Korean. An automatic join from `SPRAG_TEAM_TOKEN` stays silent and tries again at the next session start.
- **sprag.io/team has an organization panel.** It offers an organization switcher, the plan, a bar of seats used against the limit, owner editing of the limit and admins, a team list with owner emails and seat counts, admin reassignment of team owners, and creating a new team in the selected organization. Member rows show which machine shares a seat, and admins can merge or unmerge seats. The prompt-capture switch reads the plan from the organization and stays locked with an explanation unless it is Business.
- **The docs and the pricing FAQ follow the new seat rules.** docs/TEAM.md and docs/TEAM.ko.md gain an "Organizations and seats" section, and the "How are seats counted?" answer on sprag.io/pricing now describes per-organization purchase, merging a second machine, and refusal past the limit.

## 한국어

- **팀 위에 조직이 생겼고, 좌석은 조직 단위로 셉니다.** 좌석 하나는 최근 30일 안에 활동한 컴퓨터 한 대(멤버 키 하나)이고, 같은 사람의 두 번째 컴퓨터는 조직 관리자가 첫 번째 좌석에 합칠 수 있습니다. 조직마다 좌석 한도가 있으며 한도를 넘는 참여는 초과 과금이나 유예 없이 거절됩니다. 조직 소유자는 한도를 정하고 관리자를 지정하며, 관리자는 팀을 만들고 팀 소유자를 지정하고 조직의 모든 팀을 봅니다. 요금제(team·business)는 이제 조직에 붙으며 Sprag 가 설정하고 고객은 바꿀 수 없습니다.
- **`sprag team create --org <조직 ID>` 로 기존 조직 안에 팀을 만듭니다.** 로그인 세션으로 서버의 `team_create` 를 호출하며, `--org` 를 생략하면 팀 이름의 새 조직이 생겨 3.70.0 과 같게 동작합니다. 출력에 조직 이름과 사용 중인 좌석 수(예: 1/5)가 더해지고, `sprag team status` 는 조직 이름을 보여 줍니다.
- **한도에 걸린 참여는 안내와 함께 종료 코드 1로 끝납니다.** 서버의 `seat limit reached` 를 별도 오류로 받아 "이 조직에 남은 자리가 없습니다. Sprag 관리자에게 자리 한도를 늘려 달라고 요청한 뒤 다시 참여하세요"(영어·한국어)를 출력합니다. `SPRAG_TEAM_TOKEN` 자동 참여는 조용히 넘어가고 다음 세션 시작 때 다시 시도합니다.
- **sprag.io/team 에 조직 패널이 생겼습니다.** 조직 전환, 요금제, 한도 대비 사용 좌석 막대, 소유자의 한도 수정과 관리자 추가·제거, 소유자 이메일과 좌석 수가 붙은 팀 목록, 관리자의 팀 소유자 변경, 새 팀을 선택한 조직에 만들기를 한 화면에서 합니다. 멤버 행에는 "OO님과 자리를 같이 씁니다"가 보이고 관리자는 자리 합치기와 해제를 합니다. 프롬프트 수집 스위치는 요금제를 조직에서 읽어, 비즈니스가 아니면 안내와 함께 잠깁니다.
- **문서와 요금 FAQ 를 새 좌석 규칙에 맞췄습니다.** docs/TEAM.md 와 TEAM.ko.md 에 "조직과 좌석" 절을 더했고, sprag.io/pricing 의 "좌석은 어떻게 세나요?" 답변을 조직 단위 구매와 합치기, 한도 초과 거절 기준으로 바꿨습니다.
