- **Permission levels are now superuser, owner and admin, and teams sit inside organizations.** The superuser (Sprag staff) sets the plan and the seat limit, suspends organizations, adds owners and sees every organization at sprag.io/ops/; an owner (a company's top level) appoints and removes admins and does everything an admin does; an admin (a company's management level) creates teams and manages members, rules and seats. The former team-owner level is gone: the person who created a team has no special rights, and only the organization's owners and admins and the superuser manage teams.
- **`SPRAG_NO_TEAM_SYNC=1` now stops every usage upload without hiding the machine from the team.** A joined machine sends one status-only call, `member_set_sync` with no usage data, the first time it sees the switch on and one more when it is off again, then uploads immediately. A paused machine keeps its seat until an owner or admin removes it. The old name `CTS_NO_TEAM_SYNC` is still read.
- **Owners and admins get a seat roster on sprag.io/team.** Each machine shows its upload switch (On/Off), a signal (ok, late, paused, silent, left or removed), last upload, last contact, paused since and version, with remove (frees the seat and stops the machine's key), restore (only machines an owner or admin removed, within the seat limit) and seat merge. An activity log lists joined, paused, resumed, left, removed and restored events with who did each one: member, owner, admin or superuser.
- **A seat is now a machine that has not left and either sent anything in the last 30 days or is paused.** Seats are counted per organization, a second machine of the same person can be merged into the first seat, and the seat limit is set by Sprag, with a join past it refused with no overage billing and no grace period. To add seats, write to sales@sprag.io. The plan (pro or enterprise) belongs to the organization, and only Sprag can change it.
- **`sprag team create --org <org-id>` creates a team inside an existing organization.** It calls the server's `team_create` with your sign-in session; without `--org` a new organization named after the team is created, so it behaves as in 3.70.0. The output now includes the organization name and how many seats are used (for example 1/5), and `sprag team status` shows the organization name.
- **A join refused at the seat limit now ends with a clear message and exit code 1.** The CLI maps the server's `seat limit reached` to a typed error and prints that the organization has no free seat and the organization owner or admin should ask for more seats, in English or Korean. An automatic join from `SPRAG_TEAM_TOKEN` stays silent and tries again at the next session start.
- **The docs follow the new roles, switch and seat rules.** docs/TEAM.md and docs/TEAM.ko.md rewrite the roles section and add "The upload switch" and "The seat roster", docs/INSTALL.md and docs/INSTALL.ko.md mention the one status-only call in the network table, and the "How are seats counted?" answer on sprag.io/pricing describes per-organization purchase, merging and refusal past the limit.
- **The seat roster can show each machine's operating system and CPU architecture.** A joined machine sends the OS name and version (for example macOS 26, Windows 11, Ubuntu 24.04) and the CPU architecture (arm64 or x64) once after joining and again only when it changes. No hostname, user name or path is sent, nothing is sent while uploads are switched off, and `sprag team status --show-payload` shows the exact values.
- **Paid plans are renamed: Team is now Pro, Business is now Enterprise.** Pro ($5 per seat per month) covers the spend and savings dashboard, seats and team rules. Enterprise ($10 per seat per month) adds prompt capture and a per-user prompt usage page on sprag.io/team. The plan is stored as `pro` or `enterprise` and existing organizations were converted. Volume or annual invoicing is now called Custom (sales@sprag.io).
- **Enterprise teams upload the prompts you type about every 30 minutes.** It runs only when the team policy has prompt capture on, and sends the time, project folder name and text (cut at 20,000 characters) of prompts typed in your main Claude Code and Codex sessions to the server's `prompt_chunk_put`. Assistant replies, tool output, file contents, subagent transcripts and file paths are never sent, and `sk-`, `ghp_`, `AKIA` and `Bearer` tokens, private key blocks and `KEY=`, `TOKEN=`, `PASSWORD=`, `SECRET=` assignments become `[redacted]`. Nothing written before the policy reached the machine is uploaded (the first time capture is seen on, the end of every file is remembered), and when the policy turns off the position file `prompts-offsets.json` is deleted. A prompt submit checks only a local timer and, after 30 minutes, a detached background process uploads; the daily aggregate stays at every 6 hours. One run sends at most 2,000 prompts or 8 MB and the rest waits. `sprag team status` shows the capture state and the last upload, and `--show-payload` shows the waiting count and one redacted example. To stop, switch the team policy off, set `SPRAG_NO_TEAM_SYNC=1` or run `sprag team leave`.
- **A failed sync retries within the hour and catches up missed days.** When the daily aggregate upload fails, for example with the network down, it is retried after 15, 30 and then 60 minutes (60 at most) instead of after 6 hours, and returns to the 6-hour rhythm once it succeeds. The CLI remembers the last day it uploaded and re-sends from the day before it through today (up to 30 days, 30 on the first sync), so a machine that was offline for days catches up on its first success. A prompt submit also reads only a local file to see whether this sync is needed and, if so, starts a detached background process. `lastSyncAt` now means the last success.
- **Dashboard spend and savings can be shown for a date range.** The range control at the top of sprag.io/team and sprag.io/ops (7d, 30d, 90d, This month, Last month, Custom) now drives the members table, the usage chart, prompt usage and the organization table, with the last 30 days as the default. The choice stays in the address as `from` and `to`, up to 365 days. The server gives `ops_orgs` and `org_prompt_usage` optional range arguments and adds `team_member_usage`, and the overlong stat cells in the organization header no longer overflow
- **Environment variables are renamed from `CTS_` to `SPRAG_`.** The 15 variables that still carried the old package name, such as `SPRAG_NO_TEAM_SYNC`, `SPRAG_NO_UPDATE_CHECK`, `SPRAG_LANG` and `SPRAG_DEBUG`, are now read under the new name first. The `CTS_` names already set in your shell, CI or Claude Code managed settings keep working, and `SPRAG_` wins when both are set. Docs, help text and install output now show the new names.
- **Presets are published from sprag.io/ops, and every CLI pulls them read-only once a day.** The superuser edits the ratchet presets, model-routing presets and delegation agents as tables on the new Presets page of /ops, saves a draft, and publishes it signed with an ECDSA P-256 key kept in the browser. History restores an earlier version, and the same page creates, backs up, imports and fingerprints the key. A CLI applies a fetched bundle only when its signature verifies against a key in `src/preset-sign.js` and otherwise uses the presets bundled in the package. `sprag presets status` shows which copy is in use and why, and `SPRAG_NO_PRESET_SYNC=1` turns the fetch off.

## 한국어

- **권한 단계가 슈퍼유저, 오너, 어드민으로 정리됐고 팀은 조직 안에 속합니다.** 슈퍼유저(Sprag 직원)는 요금제와 좌석 한도를 정하고, 조직을 정지하고, 오너를 추가하고, sprag.io/ops/ 에서 모든 조직을 봅니다. 오너(회사의 최상위 단계)는 어드민을 지정하거나 해제하고 어드민이 하는 일을 모두 합니다. 어드민(회사의 관리 단계)은 팀을 만들고 구성원과 룰과 좌석을 관리합니다. 예전의 팀 소유자 단계는 없어졌습니다. 팀을 만든 사람에게는 특별한 권한이 없고, 팀은 조직의 오너와 어드민, 슈퍼유저만 관리합니다.
- **`SPRAG_NO_TEAM_SYNC=1` 은 이제 팀에서 숨지 않고 사용량 업로드만 모두 멈춥니다.** 참여한 컴퓨터는 스위치가 켜진 것을 처음 봤을 때 상태만 담은 호출 `member_set_sync` 를 한 번(사용량 데이터 없음), 다시 꺼졌을 때 한 번 더 보내고 바로 업로드합니다. 멈춘 컴퓨터는 오너나 어드민이 내보내기 전까지 좌석을 유지합니다. 옛 이름 `CTS_NO_TEAM_SYNC` 도 계속 읽습니다.
- **오너와 어드민은 sprag.io/team 에서 좌석 현황을 봅니다.** 컴퓨터마다 업로드 스위치(On/Off), 신호(ok, late, paused, silent, left, removed), 마지막 업로드, 마지막 연락, 멈춘 시점, 버전이 보이고, 내보내기(좌석을 비우고 그 컴퓨터의 키를 막음), 복구(오너나 어드민이 내보낸 컴퓨터만, 좌석 한도 안에서), 좌석 합치기를 할 수 있습니다. 활동 기록에는 참여, 멈춤, 재개, 탈퇴, 내보내기, 복구가 누가 했는지(구성원, 오너, 어드민, 슈퍼유저)와 함께 남습니다.
- **좌석은 팀을 떠나지 않았고, 최근 30일 안에 무엇이든 보냈거나 업로드를 멈춘 컴퓨터 한 대입니다.** 좌석은 조직 단위로 세고, 같은 사람의 두 번째 컴퓨터는 첫 번째 좌석에 합칠 수 있습니다. 한도는 Sprag가 정하며 한도를 넘는 참여는 초과 과금이나 유예 없이 거절됩니다. 좌석을 늘리려면 sales@sprag.io 로 문의합니다. 요금제(pro·enterprise)는 조직에 붙으며 Sprag만 바꿀 수 있습니다.
- **`sprag team create --org <조직 ID>` 로 기존 조직 안에 팀을 만듭니다.** 로그인 세션으로 서버의 `team_create` 를 호출하며, `--org` 를 생략하면 팀 이름의 새 조직이 생겨 3.70.0 과 같게 동작합니다. 출력에 조직 이름과 사용 중인 좌석 수(예: 1/5)가 더해지고, `sprag team status` 는 조직 이름을 보여 줍니다.
- **한도에 걸린 참여는 안내와 함께 종료 코드 1로 끝납니다.** 서버의 `seat limit reached` 를 별도 오류로 받아 "이 조직에 남은 좌석이 없습니다. 조직 오너나 어드민에게 좌석 추가를 요청한 뒤 다시 참여하세요"(영어·한국어)를 출력합니다. `SPRAG_TEAM_TOKEN` 자동 참여는 조용히 넘어가고 다음 세션 시작 때 다시 시도합니다.
- **문서를 새 권한 단계와 스위치, 좌석 규칙에 맞췄습니다.** docs/TEAM.md 와 TEAM.ko.md 는 역할 절을 고쳐 쓰고 "업로드 스위치"와 "좌석 현황"을 더했습니다. docs/INSTALL.md 와 INSTALL.ko.md 의 네트워크 표에는 상태만 담은 호출 한 번을 적었고, sprag.io/pricing 의 "좌석은 어떻게 세나요?" 답변은 조직 단위 구매와 합치기, 한도 초과 거절 기준으로 바꿨습니다.
- **좌석 현황에서 컴퓨터마다 OS 와 CPU 아키텍처를 볼 수 있습니다.** 참여한 컴퓨터가 OS 이름과 버전(예: macOS 26, Windows 11, Ubuntu 24.04), CPU 아키텍처(arm64, x64)를 참여 직후 한 번 보내고 이후에는 바뀔 때만 다시 보냅니다. 호스트 이름, 사용자 이름, 경로는 보내지 않습니다. 업로드를 멈춘 동안에는 보내지 않고, `sprag team status --show-payload` 에서 보내는 값을 확인합니다.
- **유료 요금제 이름이 바뀌었습니다. Team 은 프로, 비즈니스는 엔터프라이즈입니다.** 프로(좌석당 월 $5)는 비용·절감 대시보드, 좌석, 팀 룰을 쓰고, 엔터프라이즈(좌석당 월 $10)는 여기에 프롬프트 수집과 sprag.io/team 의 사용자별 프롬프트 사용량 화면이 더해집니다. 서버에는 `pro`, `enterprise` 로 저장되고 기존 조직은 모두 옮겼습니다. 대량 구매나 연간 청구는 맞춤 계약(sales@sprag.io)으로 부릅니다.
- **엔터프라이즈 팀은 직접 입력한 프롬프트를 약 30분마다 올립니다.** 팀 정책에서 프롬프트 수집이 켜진 경우에만 동작하며, 메인 Claude Code 와 Codex 세션에서 입력한 프롬프트의 시각, 프로젝트 폴더 이름, 본문(최대 20,000자)을 서버의 `prompt_chunk_put` 으로 보냅니다. 어시스턴트 답변, 도구 출력, 파일 내용, 서브에이전트 기록, 파일 경로는 보내지 않고, `sk-`·`ghp_`·`AKIA`·`Bearer` 토큰, 개인 키 블록, `KEY=`·`TOKEN=`·`PASSWORD=`·`SECRET=` 대입은 `[redacted]` 로 바꿉니다. 정책이 이 컴퓨터에 닿기 전에 쓴 기록은 올리지 않고(처음 켜질 때 모든 파일의 끝을 기억합니다), 정책이 꺼지면 위치 파일 `prompts-offsets.json` 을 지웁니다. 프롬프트를 제출할 때 로컬 타이머만 확인해 30분이 지났으면 분리된 백그라운드 프로세스가 올리고, 하루 단위 집계는 그대로 6시간마다입니다. 한 번에 최대 2,000건 또는 8MB이며 나머지는 다음 차례로 넘어갑니다. `sprag team status` 는 수집 상태와 마지막 업로드를, `--show-payload` 는 대기 건수와 가려진 예시 하나를 보여 줍니다. 멈추려면 팀 정책을 끄거나 `SPRAG_NO_TEAM_SYNC=1` 을 설정하거나 `sprag team leave` 를 실행합니다.
- **실패한 동기화는 1시간 안에 다시 시도하고, 빠진 날을 따라잡습니다.** 하루 단위 집계 업로드가 네트워크 문제로 실패하면 6시간을 기다리지 않고 15분, 30분, 60분 간격(최대 60분)으로 다시 시도하며, 성공하면 6시간 주기로 돌아갑니다. 마지막으로 올린 날짜를 기억해 그 전날부터 오늘까지(최대 30일, 처음에는 30일) 다시 보내므로 며칠 오프라인이던 컴퓨터도 첫 성공에서 따라잡습니다. 프롬프트를 제출할 때도 로컬 파일만 읽어 이 동기화가 필요한지 확인하고, 필요하면 분리된 백그라운드 프로세스를 띄웁니다. `lastSyncAt` 은 이제 마지막 성공 시각입니다.
- **대시보드 지출·절감 수치를 기간으로 고를 수 있습니다.** sprag.io/team 과 sprag.io/ops 맨 위의 기간 선택(7일, 30일, 90일, 이번 달, 지난 달, 직접 선택)이 멤버 표, 사용량 차트, 프롬프트 사용량, 조직 표의 지출·절감에 적용되고, 기본값은 최근 30일입니다. 고른 기간은 주소의 `from`, `to` 에 남고 최대 365일입니다. 서버는 `ops_orgs`, `org_prompt_usage` 에 선택 인자를 더하고 `team_member_usage` 를 새로 만들었으며, 조직 머리말의 통계 칸이 길어져 넘치던 문제도 고쳤습니다
- **환경변수 접두사를 `CTS_` 에서 `SPRAG_` 로 바꿨습니다.** `SPRAG_NO_TEAM_SYNC`, `SPRAG_NO_UPDATE_CHECK`, `SPRAG_LANG`, `SPRAG_DEBUG` 처럼 옛 패키지 이름이 남아 있던 변수 15개가 새 이름을 먼저 읽습니다. 셸, CI, Claude Code 관리 설정에 이미 넣어 둔 `CTS_` 이름도 그대로 동작하고, 둘 다 있으면 `SPRAG_` 가 우선합니다. 문서와 도움말, 설치 출력은 새 이름으로 안내합니다.
- **프리셋을 sprag.io/ops 에서 게시하고, 모든 CLI 가 하루에 한 번 읽기 전용으로 받아 갑니다.** 슈퍼유저는 /ops 의 새 프리셋 화면에서 래칫 프리셋, 모델 라우팅 프리셋, 위임 에이전트를 표로 고치고 초안으로 저장한 뒤, 브라우저에 보관한 ECDSA P-256 키로 서명해 게시합니다. 이력에서 이전 버전으로 되돌릴 수 있고, 키는 만들기, 백업 내려받기, 가져오기, 지문 확인을 같은 화면에서 합니다. CLI 는 서명이 `src/preset-sign.js` 의 키로 확인될 때만 받은 번들을 적용하고, 그렇지 않으면 패키지에 동봉된 프리셋을 씁니다. `sprag presets status` 가 어느 쪽을 왜 쓰는지 보여 주고, `SPRAG_NO_PRESET_SYNC=1` 로 받아 오기를 끕니다.
