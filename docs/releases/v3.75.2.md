- **The default team display name is now a random member id instead of your OS user name.** When `sprag team join` or `sprag team create` ran without `--name`, the OS user name went to the team server as is. Each machine now creates an id such as `member-3f9a2c71` once and keeps it in the user data directory, and it stays a single id even when two processes start at once or a write fails. Members who already joined keep the name the server has, and `--name` still overrides the default.
- **Team device info no longer includes the CPU architecture.** Only the OS name and version are sent. The `arch` argument stays in the RPC so its shape does not change, and it is always empty.
- **The update check now asks the npm registry you configured.** It reads `npm_config_registry` or the `registry=` line in `~/.npmrc`, accepts https URLs only, and never falls back to npmjs, so a machine that can reach only an internal registry sends nothing outside. Registry auth tokens are not sent, so the check fails on a registry that requires authentication even for reads. Refusal messages show only the URL's origin, never credentials.

## 한국어

- **팀 표시 이름의 기본값이 OS 사용자 이름에서 무작위 구성원 ID로 바뀌었습니다.** `sprag team join` 과 `sprag team create` 에서 `--name` 을 생략하면, 전에는 OS 사용자 이름이 그대로 팀 서버에 올라갔습니다. 이제 컴퓨터마다 한 번 만드는 `member-3f9a2c71` 같은 ID를 쓰고, 이 ID는 사용자 데이터 디렉터리에 보관합니다. 두 프로세스가 동시에 시작하거나 쓰기가 실패해도 한 컴퓨터는 ID를 하나만 가집니다. 이미 참여한 구성원은 서버에 저장된 이름을 그대로 쓰고, `--name` 으로 언제든 바꿀 수 있습니다.
- **팀 기기 정보에서 CPU 아키텍처를 뺐습니다.** 이제 OS 이름과 버전만 보냅니다. RPC 형식을 유지하려고 `arch` 인자는 남겨 두되 항상 빈 값을 넣습니다.
- **업데이트 확인이 사용자가 설정한 npm 레지스트리에 묻습니다.** `npm_config_registry` 나 `~/.npmrc` 의 `registry=` 줄을 읽고, https 주소만 받으며, 실패해도 npmjs 로 대신 묻지 않습니다. 사내 레지스트리만 열린 환경에서 외부로 요청이 나가지 않습니다. 레지스트리 인증 토큰은 보내지 않으므로, 읽기에도 인증이 필요한 레지스트리에서는 확인이 실패합니다. 거절 메시지에는 주소의 origin 만 나오고 인증 정보는 나오지 않습니다.
