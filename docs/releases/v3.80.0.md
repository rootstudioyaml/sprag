
- **A machine that joined a team shows its member id and its office animal in the statusline.** The chip reads like `member-1e500474 🦊 Fox`, sits just before the version chip, and names the animal in your configured language. The 5-minute team sync fetches only your own standing from the server and stores it in `team.json`, so nobody else's figures are downloaded; the statusline reads that file alone and falls back to the member id when the server does not offer the standing yet or it is more than a day old.
- **The server no longer counts the usage of a rejoined machine twice.** A machine that rejoined through a row created before machine ids existed re-uploaded its last 30 days while the left row kept the same days, which inflated the organization's spend and savings. An upload now removes those days from left rows of the same machine, a join reuses that old row, and the duplicates already stored have been cleaned up.

## 한국어

- **팀에 참여한 컴퓨터의 statusline 에 멤버 ID와 사무실 동물이 나옵니다.** `member-1e500474 🦊 여우` 처럼 버전 칩 바로 앞에 표시되며, 동물 이름은 설정한 언어를 따릅니다. 동물은 5분마다 도는 팀 동기화가 서버에서 본인 순위만 받아 `team.json` 에 저장한 값이고, 다른 사람의 수치는 받지 않습니다. statusline 은 이 파일만 읽으며, 서버가 아직 지원하지 않거나 하루 넘게 갱신되지 않았으면 멤버 ID만 보여 줍니다.
- **다시 참여한 컴퓨터의 사용량이 두 번 집계되던 문제를 서버에서 고쳤습니다.** 컴퓨터 ID가 도입되기 전에 만든 행으로 다시 참여하면 새 행이 지난 30일을 다시 올리는데, 나간 행에도 같은 날짜가 남아 조직 합계의 지출과 절감이 부풀었습니다. 이제 업로드가 같은 컴퓨터의 나간 행에서 그 날짜를 지우고, 참여할 때 그 옛 행을 다시 씁니다. 이미 쌓인 중복도 정리했습니다.
