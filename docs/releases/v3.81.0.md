- **Update checks and team sync now work behind a corporate proxy.** On Node 22.19, 24.5 or later, Sprag's requests trust the operating system's certificate store (macOS Keychain, Windows certificate store, the Linux system bundle) on top of Node's bundled roots and `NODE_EXTRA_CA_CERTS`. Where a proxy re-signs HTTPS with a root installed only in the system store, the update check, preset sync, team sync and feedback form used to fail quietly with `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`; they now go through with no extra setup. The store is read once, just before the first request and never while the statusline renders, and `SPRAG_SYSTEM_CA=0` turns it off.

## 한국어

- **회사 프록시 뒤에서도 업데이트 확인과 팀 동기화가 동작합니다.** Node 22.19·24.5 이상이면 Sprag 이 보내는 요청이 내장 루트 인증서와 `NODE_EXTRA_CA_CERTS` 에 더해 운영체제 인증서 저장소(macOS 키체인, Windows 인증서 저장소, Linux 시스템 번들)도 신뢰합니다. 시스템 저장소에만 설치된 루트 인증서로 HTTPS 를 다시 서명하는 환경에서 `UNABLE_TO_GET_ISSUER_CERT_LOCALLY` 로 조용히 실패하던 업데이트 확인, 프리셋 동기화, 팀 동기화, 피드백 전송이 별도 설정 없이 통과합니다. 저장소는 첫 요청 직전에 한 번만 읽고 statusline 을 그리는 동안에는 읽지 않으며, `SPRAG_SYSTEM_CA=0` 으로 끌 수 있습니다.
