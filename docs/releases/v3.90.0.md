- **Delegation savings are priced on a new basis (v3), and the same delegation now counts for about 2.7 times what it did.** The old figure kept the subagent's tokens and only swapped in the main model's prices. Had the main model done the work itself, though, it would have re-read its own session context (about 260k tokens on average on this machine) at the cache-read price on every call, and the tool output it gathered would have stayed in that context and been re-read on every later call, up to the next compaction and at most 50 calls. v3 counts both in the counterfactual and charges the delegation's own overhead, the prompt the main model writes and the result that stays in its context, against the saving. Every price keeps cache writes and reads apart and comes from the list price or the LiteLLM gateway, and a run with an unknown price is not priced. On this machine's last 14 days, the 87 rule-attributed runs went from $77.93 to $209.67, with none negative. A run whose inputs cannot be found in the transcripts falls back to the old formula and is marked basis v2. The ledger moves to version 3 and keeps the old values of events outside the scan window. v3 assumes the main model would have needed as many calls as the subagent, so work the main model would have finished in fewer calls saved less than shown. `route-scan savings` also stops saying the baseline is the model that handled the category before the rule, and names what the code uses: the priciest model on the episode.
- **Delegation hints push harder toward delegating as a usage limit fills up.** On a prompt a rule matched, the hint adds "when in doubt, delegate" once the fullest limit window passes 70%, and past 90% it treats multi-step work as delegable too and suggests the user switch the main model with `/model`. The windows are the Claude subscription limits the statusline receives (5-hour and 7-day) together with a LiteLLM gateway budget; the statusline used to save its snapshot before merging the gateway budget, so the prompt hook never saw it. Prompts kept on the main model, such as design, security or deploys, get no line, and neither the target tier nor the output caps change.
- **Rule health is judged against the session model's own failure rate.** When the session model also fails often on the same kind of work, those failures are not the delegation's fault, so a rule goes to review only when its delegated failure rate clears the session model's rate, with 20% as the floor. `route-scan rules` shows the session model's rate next to the delegated one; on this machine the command-running rule stood at 9% delegated against 8% direct.
- **In the ops console the superuser can appoint and remove organization admins, as an owner can.** The add button now reads "Add admin" or "Add owner" to match the role picker.

## 한국어

- **위임 절감액의 계산 기준을 바꿨습니다(v3). 같은 위임이 이전보다 약 2.7배 큰 금액으로 잡힙니다.** 지금까지는 서브에이전트가 쓴 토큰을 그대로 두고 단가만 메인 모델로 바꿔 비교했습니다. 그러나 메인 모델이 그 일을 직접 했다면, 호출할 때마다 자기 세션 컨텍스트(이 컴퓨터에서는 평균 약 26만 토큰)를 캐시 읽기 단가로 다시 읽었을 것입니다. 또 모은 도구 결과가 메인 컨텍스트에 남아, 이후 호출(다음 압축까지, 최대 50회)마다 다시 읽혔을 것입니다. v3는 이 두 비용을 반사실에 넣습니다. 반대로 위임 프롬프트를 쓰는 비용과, 돌아온 결과가 메인 컨텍스트에 남아 다시 읽히는 비용은 실제 비용에 더해 뺍니다. 단가는 모두 캐시 쓰기·읽기를 구분한 정가나 LiteLLM 게이트웨이 가격을 쓰고, 가격을 모르면 계산하지 않습니다. 이 컴퓨터의 14일 기록에서 룰이 위임한 87건은 $77.93에서 $209.67이 되었고, 손해로 계산된 건은 없었습니다. 필요한 값을 기록에서 찾지 못한 실행은 이전 방식으로 계산하고 basis v2로 표시합니다. 원장은 버전 3이 되며, 스캔 기간 밖의 이전 기록은 이전 값을 유지합니다. 메인 모델이 서브에이전트와 같은 횟수의 호출로 일을 끝냈다고 가정하므로, 메인이 더 적은 호출로 끝냈을 작업에서는 실제 절감이 이보다 작습니다. `route-scan savings` 가 비교 기준을 "룰 승격 전 그 유형을 처리하던 모델"이라고 안내하던 문구도, 실제 계산대로 "에피소드에서 가장 비싼 모델"로 고쳤습니다.
- **사용량 한도가 차오르면 위임 힌트가 위임을 더 권합니다.** 위임 룰이 걸린 요청에서, 가장 많이 찬 한도 창이 70%를 넘으면 "판단이 애매하면 위임하십시오"를 덧붙입니다. 90%를 넘으면 여러 단계 작업도 위임하고, 메인 모델을 바꾸는 것(`/model`)을 사용자에게 제안하라고 덧붙입니다. 한도는 상태줄이 받은 Claude 구독 한도(5시간·7일)와 LiteLLM 게이트웨이 예산을 함께 봅니다. 상태줄이 LiteLLM 예산을 합치기 전에 스냅샷을 저장해서 프롬프트 훅이 예산을 보지 못하던 문제도 고쳤습니다. 설계·보안·배포처럼 메인 모델에 남기는 요청에는 덧붙이지 않고, 위임 대상 티어와 출력 상한도 바꾸지 않습니다.
- **위임 룰의 건강도를 세션 모델의 실패율과 비교해 판정합니다.** 같은 유형을 세션 모델이 직접 처리할 때도 자주 실패한다면, 그 실패는 위임 탓이 아닙니다. 그래서 위임 실패율이 세션 모델의 실패율(하한 20%)을 넘을 때만 재검토로 넘깁니다. `route-scan rules` 는 위임 에러율 옆에 직접 처리했을 때의 실패율을 함께 보여 줍니다. 이 컴퓨터에서는 명령 실행 룰이 위임 9%, 직접 처리 8%였습니다.
- **ops 콘솔에서 슈퍼유저가 오너처럼 조직 관리자를 지정하고 해제할 수 있습니다.** 추가 버튼의 이름도 역할 선택에 맞춰 "관리자 추가" 또는 "오너 추가"로 바뀝니다.
