# evals/: replayed delegation cases

This directory is the tracked corpus behind https://sprag.io/proof/. Each case is a real delegation that was replayed headlessly under several model and effort settings, graded blind against a rubric fixed before the run, and priced from the transcripts.

| Path | What it is |
| --- | --- |
| `index.json` | case ids in display order |
| `conditions.json` | the model, effort and prompt settings a lane can use |
| `rounds.json` | rounds (`conditions` or `effort`) with their dates |
| `cases/<id>.json` | one public case: wording, runs, baseline, optional repeats |
| `summary.json`, `SUMMARY.md` | generated; the npm package ships the JSON and `sprag proof` reads it |

Everything else is generated by `node scripts/evals/build.mjs` (`npm run evals:build`): `site/proof/data.json`, the summary files and the evidence blocks in the READMEs. `npm run evals:check` verifies them without writing. Do not edit generated files by hand.

## The loop

Every script below lives in `scripts/evals/` and has an `npm run evals:<name>` alias. Round directories live under the work directory (step 2).

1. **Harvest.** `node scripts/evals/harvest.mjs [--days 30] [--project <substring>]` scans `~/.claude/projects` for `Agent`/`Task` delegations, skips turns the harness injected, masks secrets, drops prompts already used in a round, and writes `candidates.jsonl` (347 today) into the work directory. It prints counts per agent and effort.
2. **Pick, then fix the rules before running.** Choose candidates and create a round directory `<work>/rounds/<id>/` with:
   - `cases/<case>.md`: the delegation prompt, with `{{REPO}}` where the repository path goes. Replay substitutes the worktree path.
   - `rubric/<case>.md`: the scoring rubric. **Write it before step 3.** Replay refuses to start without it. Graders have no tools, so put the answer key (what the code actually says, with file and line) inside the rubric.
   - `round.json`: see below.
3. **Replay.** `node scripts/evals/replay.mjs <round-dir> --dry-run` prints the plan, a token estimate and every full command line. Then `--yes` runs them (`--only <case>` limits it). Replay creates a detached git worktree at `commit`, runs `claude -p` in it per case and condition, and writes `reports/`, `transcripts/`, `cost.json`, `blocked.json` and `runs.json`. It never uses `bypassPermissions`: runs use `--permission-mode dontAsk`, and without `"write": true` on the case they also get `--disallowedTools Edit Write NotebookEdit`. Finished runs are skipped on a rerun; failed runs are not recorded, so a rerun retries them.
4. **Grade.** `node scripts/evals/grade.mjs <round-dir>` prints the plan and an estimate; `--yes` runs one Opus grader per case (at most 3 at once, `--case <id>` limits it). Reports get randomized labels (P, Q, R, ...), model and effort lines are stripped, and the blind prompt is saved to `blind/<case>.md`. The label key goes to `blind_key.json`, raw replies to `grading/`, and the unblinded scores are merged into `scores_by_run.json`. A reply that is not valid JSON or fails validation is reported and not merged; rerun to retry that case (`--regrade` redoes graded cases).
5. **Write `public.json`** in the round directory: `{ "cases": [ ... ] }`, one entry per case to publish.

   ```json
   {
     "id": "1001", "kind": "lookup", "story": "cost-down", "publish": true,
     "recommended": "haiku-low",
     "storyNote": { "ko": "...", "en": "..." },
     "title": { "ko": "...", "en": "..." },
     "userPrompt": { "ko": "...", "en": "..." },
     "task": { "ko": "...", "en": "..." },
     "truth": { "ko": "...", "en": "..." },
     "lesson": { "ko": "...", "en": "..." }
   }
   ```

   `story` is `quality-up`, `cost-down` or `context`. `recommended` is the id of one of the round's conditions. `publish` must be exactly `true`; `"ask"` or `false` entries are skipped. Write the user prompt without personal context. An optional `"screenshot": "assets/<file>.png"` needs the image copied into `site/proof/assets/` by hand.
6. **Publish.** `node scripts/evals/publish.mjs <round-dir> [--case <id>] [--replace] [--yes]`. Without `--yes` it builds the cases in memory, validates the whole corpus and prints a summary. With `--yes` it writes `cases/<id>.json`, appends to `index.json`, adds the round to `rounds.json` and any new conditions to `conditions.json`, then runs `build.mjs`. It refuses to overwrite an existing case without `--replace`. An `effort` round does not create a case: it adds `repeats` to the case that its `conditions` round already published.
7. **Commit and push.** Commit `evals/`, `site/proof/data.json` and the README blocks. A push to `main` deploys the site (the page is live after the Pages run). The npm summary and `sprag proof` ship with the next release.

### round.json

```json
{
  "id": "r3", "date": "2026-11-08", "kind": "conditions",
  "repo": "/path/to/repo", "commit": "0a4333c",
  "repeats": 1, "concurrency": 2,
  "allowedTools": ["Read", "Grep", "Glob", "Bash"],
  "conditions": [
    { "key": "A", "id": "haiku-low", "model": "claude-haiku-5-5", "effort": "low", "agent": "t2-explore", "prompt": "original" },
    { "key": "B", "id": "sonnet-high", "model": "claude-sonnet-5-5", "effort": "high", "prompt": "original" },
    { "key": "C", "id": "opus-direct", "model": "claude-opus-5-5", "effort": "high", "prompt": "original", "role": "baseline" }
  ],
  "cases": [
    { "id": "1001", "prompt": "cases/1001.md", "rubric": "rubric/1001.md", "agents": { "A": "t2-runner" } },
    { "id": "1002", "prompt": "cases/1002.md", "rubric": "rubric/1002.md", "write": true }
  ]
}
```

- `model` is the full model id passed to `--model`; published runs show only the family (haiku, sonnet, opus).
- Exactly one condition of a `conditions` round has `"role": "baseline"`. Savings are measured against it.
- `agents` overrides a condition's agent for one case (case 404 ran lane A as `t2-runner`). `write: true` lets that case edit files in the worktree.
- `allowedTools` is optional. `dontAsk` denies every tool that is not allowed, so list the tools the cases need if your settings do not already allow them. A case with `write: true` also gets `Edit` and `Write`.
- `prompt: "improved"` conditions need an `improvedPrompt` file on every case.
- An `effort` round sets `repeats` above 1 and uses conditions that differ only in effort. Run keys are `<case>-<key>-<rep>`.

## Cost

Replays and grading run through the Claude Code CLI with `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` removed from the child environment, so they are billed to the Max subscription and count toward its limits, not to API credit. Both scripts do nothing without `--yes`. Show the user the printed estimate and get a confirmation before adding `--yes`. The estimate comes from past rounds' averages per model; Opus runs and web research dominate it.

## Privacy

- Transcripts, reports, prompts and candidates stay under the git-ignored work directory: `handoff/evals-work/` by default, or the directory in `SPRAG_EVALS_WORK`. Never copy them into `evals/`.
- Only public fields reach `evals/`. Publishing scrubs home paths, scratch paths, the owner's names, the server repository name and e-mail addresses, masks token-shaped strings in reports, caps reports at 8000 characters and trace labels at 60, and replaces any trace label that looks like a secret with `(hidden)`.
- Publish then checks every string with the corpus privacy pattern (`privacyRe()` in `build.mjs`) and aborts on a hit, naming the field. `build.mjs` runs the same check again.
- Personal names are never written into this repository, not even as patterns. List them one per line in `<work dir>/private-names.txt` (git-ignored) or comma-separated in `SPRAG_EVALS_PRIVATE_NAMES`; scrub removes them and the privacy check blocks them. Without either only the generic patterns (home paths, scratch dirs, emails) apply, which is the CI case.

## Add a condition

Add an entry to `conditions` in `round.json` with the next free key, for example:

```json
{ "key": "E", "id": "sonnet-xhigh", "model": "claude-sonnet-5-5", "effort": "xhigh", "prompt": "original" }
```

For a new round, nothing else is needed: replay runs it, and publish adds `sonnet-xhigh` to `conditions.json` and to each case's lanes. To add a lane to a case that is already published, add the condition to that round's `round.json`, run `replay --only <case> --yes` (finished runs are skipped), grade the new reports with `grade --case <case> --yes`, then `publish --case <case> --replace --yes`. The id of a condition must not be reused with a different setup: publish stops if `conditions.json` already has that id with other values.

## Where replay sessions show up

Replay runs `claude` with the worktree as its working directory, so the sessions are written under `~/.claude/projects/` in a folder named after the worktree path (every character that is not a letter or digit becomes `-`). Replay copies each transcript into the round directory and reads cost from it. Those sessions also appear in sprag's own session stats under that project name; they are replays, not your work. Graders run in a temporary directory, so their sessions have their own folder.

## Weekly candidates

`npm run evals:weekly` harvests the delegations made since its last run, drops replay sessions, and flags the turns the user corrected right after (a narrow keyword match on the next prompt, so it under-reports; the 2026-11-07 review of 57 delegations found 4 silent losses by reading every turn). It posts the list to the sprag Slack channel with the same `SLACK_BOT_TOKEN` and `SPRAG_SLACK_CHANNEL_ID` lookup as `scripts/upstream-watch.mjs`, and moves `<work>/weekly-state.json` forward only after Slack accepts the post. `--dry-run` prints the message instead. It makes no model call.

On the maintainer's Mac a launchd job (`com.rootstudioyaml.sprag-evals-weekly`, Mondays 06:30) runs it; the log is `~/Library/Logs/sprag-evals-weekly.log`. Picking cases from the list, writing rubrics and approving a replay stay with a person and the main session.
